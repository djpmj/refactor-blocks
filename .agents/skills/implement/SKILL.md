# implement

このスキルが利用者の入口。利用者は引数なしで `$implement` と入力する。自然文の「実装してください」でも、このスキルが選ばれたら同じ手順で進める。会話で特定の対象が明示された場合は、その指定を優先する。

`.codex/agents/implementation-orchestrator.toml` のカスタムエージェントを起動し、会話上の制約を渡す。オーケストレーターが開いている Issue と関連 PR から既存の未完了対象を収集し、Issue 本文の仕様書パスを使って一件ずつ処理する。起動手段がカスタムエージェント名の選択に対応しない場合は、このファイルの `developer_instructions` を読み、親スレッドがオーケストレーターを担当する。実装や評価を親スレッドが兼ねない。

オーケストレーターは `.codex/agents/codex-implement.toml` と `.codex/agents/evaluator.toml` の役割を**別々のサブエージェントスレッド**で起動し、実装 → 独立評価 → 指摘修正の順に進める。実装者は `gpt-6-luna`、評価者は `gpt-6-sol` を使う。エージェント名を選べない起動手段では、各 TOML の指示を対応するスレッドへの依頼文に含め、起動時のモデルも指定する。別スレッドを起動できない場合は、独立評価を実施したとは報告せず、利用者に制約を伝える。Codex CLI を外部プロセスとして起動しない。

利用者にはオーケストレーターの最終報告を返す。
