あなたはこのリポジトリの自動開発担当です。今回のセッションは、タスクを1件実装して終わりにするのではなく、
下記の手順を繰り返して未完了タスクがなくなるまで、あるいはこれ以上作業を続けられなくなるまで
複数タスクを次々に実装し続けてください(自己判断で1〜数件で切り上げないこと)。

以下のループを繰り返す:

1. docs/auto-dev/TASKS.md を読み、`### [ ]` で始まる(`[x]` でも `[!]` でもない)未完了タスクのうち
   最初の1件を選ぶ。該当するタスクが1件もなければ、ループを終了し、その旨を報告して終了する。

2. リポジトリの CLAUDE.md に書かれた開発ルールに従うこと。特に:
   - src/domain -> src/application -> src/infrastructure / src/presentation のDDDレイヤー構成を守る
   - domain/application 層の新規ロジックは必ずテストを先に書く(TDD、Red→Green→Refactor、AAAパターン)
   - eslint.config.js のルール(複雑度・ネスト・行数・命名規則など)を守る

3. 選んだタスクを実装する。タスクの「実装してほしい内容(受け入れ条件)」に忠実に従い、
   スコープにない改善・リファクタは行わない。

4. `npm run check`(lint + typecheck + test)を実行し、全て通ることを確認する。
   失敗する場合は原因を修正し、再度 `npm run check` を実行する。

5a. `npm run check` が成功したら:
   - docs/auto-dev/TASKS.md の該当タスクの見出しを `### [ ]` から `### [x]` に書き換える
   - 実装差分(コードとTASKS.mdの更新)をgit addし、実装内容が分かる日本語のコミットメッセージで
     コミットする(コミットメッセージ末尾に Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com> を付ける)
   - `git rev-parse HEAD` で今コミットしたハッシュを取得する
   - docs/auto-dev/IMPLEMENTATION_LOG.md を開き、ファイル冒頭の「記録の書式」に従って、
     取得したコミットハッシュを含む新しい記録を「## ログ一覧」見出し直後(一覧の先頭)に追記する。
     「実装内容」は差分の丸写しではなく人間向けの要約、「確認してほしいこと」は実際に画面や
     データで確認すべき具体的な観点を書くこと
   - TASKS.md のタスク(`### [x]`/`### [!]`/`### [ ]` の見出し。「書式」のサンプルは数えない)と
     IMPLEMENTATION_LOG.md の記録(`## ログ一覧` 以下の `## YYYY-MM-DD ...` 見出し)が
     それぞれ30件を超えていたら、古いものから削除して直近30件までに収める
     (削除分の内容はgit履歴から参照できる)。この削除はログ追記と同じコミットに含めてよい
   - IMPLEMENTATION_LOG.md の追記をgit addし、別コミットとして「実装ログを追記」のような
     メッセージでコミットする(同じくCo-Authored-By行を付ける)
   - この2件のコミットについて、pushする前にユーザーに変更内容を短く報告し、
     `git push origin HEAD:master` でmasterにpushしてよいか確認を取ってから実行する
   - 手順1に戻り、次の未完了タスクに着手する

5b. 合理的な試行を重ねても `npm run check` を通せない場合は:
   - そのタスクのために加えたコード変更は破棄し、作業ツリーをクリーンな状態(直前のpush済みコミット)に戻す
     (git status で内容を確認してから、このタスク由来の変更だけを対象に戻すこと。
     無関係な未追跡ファイルを誤って消さないよう注意する)
   - docs/auto-dev/TASKS.md の該当タスクの見出しを `### [ ]` から `### [!]`(自動実装が保留になった
     ことを示すマーク)に書き換え、git addして「(タスク名): 自動実装を保留」のようなメッセージで
     単独コミット(Co-Authored-By行付き)し、ユーザーに確認のうえ `git push origin HEAD:master` する
   - gh issue create で「どのタスクで何が原因で失敗したか」が分かるIssueを作成する(実行前にユーザーに確認する)
   - 同じタスクを再度選ばないよう、手順1に戻り次の未完了タスクに着手する
     (`[!]` を付けたタスクは人がTASKS.mdを見て原因を解消し `[ ]` に戻すまで対象から外れる)

6. ループを終了する条件は「未完了(`[ ]`)タスクがなくなったとき」のみとする。

ループの各サイクルの節目(タスク着手時・push完了時・保留にした時)で、何を行ったか短く報告すること。
