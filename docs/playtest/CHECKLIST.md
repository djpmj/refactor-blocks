# 実機プレイの観点リスト

実機で遊んで不具合・改善点を探すときの見る場所。機械で確かめられるものは `npm run explore`
(`explore/stage-invariants.spec.ts`)が全ステージで回す。人が見る必要があるものだけを手で確かめる。

## 機械で確かめる(`npm run explore`)

- 開いただけのステージが、進捗(`refactor-blocks:progress`)に記録されていない
- ファイルの箱どうしが重なっていない
- 案内バナーがキャンバスの内側に収まり、ノードと重ならない
- 手直しの前後でメソッドエディタを開いても、画面の横スクロールが出ない
- 失敗トースト(`role="alert"`)が、何もしていないのに残っていない

## 手で見る

- 初回表示・リロード後に、開く画面が自然か(最後のステージ、ツアー、下書きの再開)
- 操作の流れ: 手直し → 組み替え → 抽出 → 移動 → 100点 → 次のステージへ、で行き止まりが無いか
- 狭い画面(幅600px)・ダークモードで、読めない・押せないものが無いか
- 失敗したとき(重複名・離れた処理の抽出・手直し前のドラッグ)の言葉が、次の一手を示しているか
- 点数・減点・ヒントの表示が、操作のたびに今のコードと食い違っていないか
- キーボードだけで、メソッドの選択・抽出・移動ができるか

## 見つけたら

1. 症状・再現手順・数値(座標・サイズ・保存値)を控える
2. 原因のコードを `grep` で特定する(直す場所が1か所か確かめる)
3. 小さな修正は `docs/specs/_template-bugfix.md`、設計判断があるものは `_template.md` で仕様にする
4. 機械で確かめられるものは、`explore/stage-invariants.spec.ts` に観点を足す
