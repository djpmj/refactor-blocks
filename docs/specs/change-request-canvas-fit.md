# change-request-canvas-fit: 変更依頼を始めたとき、部品置き場が見えて掴める大きさで図を収める

## 症状

画面 1440x900 で、上級2・上級3・上級8を100点にし、「もう一度手で直す」を終えてから「変更依頼に挑戦」を押すと、キャンバスの倍率が極端に小さくなる。

- 上級2は倍率 0.335 になる。部品(`charge()`)の高さは約7px、文字は3〜4pxで、ほぼ掴めない
- 上級8は倍率 0.45 になる
- 上級3は倍率が約0.2になる(全体を収めるのに必要な倍率。実際には実装中の下限 0.3 で止まる)。組み替えでファイルが5つに増えているため、部品置き場が図の右端に付き、キャンバスの右端(x=1080)より外の x=1132 に出る。右の依頼パネルの下に隠れて見える
- 上級3で「全体を表示」を押しても、React Flow の `minZoom`(0.3)で止まるため全体が収まらない。中央に寄せられ、部品置き場の右半分と左端の `DiscountService` が切れる

自動の「全体を表示」の下限 0.6(detail-zoom-floor)を大きく下回っている。

### 既存の仕様との関係

- `detail-zoom-floor`(#189): 自動の合わせを `DETAIL_ZOOM`(0.6)より小さくしない仕様。ただし変更依頼の実装中は「部品置き場まで見渡せるように」床を外している(`useAutoViewportFit` の `implementing ? CANVAS_MIN_ZOOM : DETAIL_ZOOM`)。今回の症状は、この床を外した経路で起きている。床の値はこの仕様では変えない
- `canvas-refit-on-resize`(#180): キャンバスの大きさが変わったら、プレイヤーが動かしていない図を合わせ直す仕様。この仕様でサイドバーを閉じたときの合わせ直しは、この仕組みにそのまま任せる
- #404「狭い画面で変更依頼を始めたとき課題サイドバーを自動で閉じる」(`ChangeRequestSidebarCloser`): 701〜1399px だけ左の課題サイドバーを閉じる。「1400px以上ならキャンバスが足りる」という前提だったが、1440px で足りないことがわかったので、この仕様で上限を外す
- `change-request-step-feedback`・`change-request-fairness`・`change-request-sample-on-ideal-base`: 変更依頼の答え合わせと解答例の仕様。表示の倍率と部品置き場の位置には触れていないので重ならない
- `blank-design-tray-display`: 白紙設計の部品置き場の見た目の仕様。位置には触れていないので重ならない

## 原因

原因は2つあり、どちらか1つを直すだけでは上級3が直らない(下の「検討した直し方」を参照)。

1. **キャンバスの幅が足りない。** 1440px では、左の課題サイドバー(`stageSidebarMaxWidth()` で 480px)と右の依頼パネル(360px)が両方開いたままになる。キャンバスは約600pxしか残らない。`ChangeRequestSidebarCloser`(`src/presentation/stage/StagePanel.tsx`)は `(min-width: 701px) and (max-width: 1399px)` のときしか左サイドバーを閉じない
2. **部品置き場が図の右端に付き、図の横幅を広げる。** 変更依頼を始めると、`withChangePart`(`src/domain/change/changePart.ts`)が部品置き場のファイル(`TRAY_FILE_ID`)をコードベースの末尾に足す。キャンバスでは、まだ位置を覚えていないファイルとして `placeFiles`(`src/presentation/canvas/keepFilePositions.ts`)が扱い、既存のファイルの**右隣**に上端をそろえて置く。部品置き場は依存を持たないので、「整列」したとき(`layoutCodebase` の `placeRows`)も1段目の右端に並ぶ。上級3では部品置き場(幅 328px + 間隔 60px)のぶん図が横に伸びる。全体を収める倍率が下限 0.3 を割るので、`autoViewport` が図の左上を基準に寄せ、右端の部品置き場がキャンバスの外に出る

部品置き場を置く場所を決めているのは `placeFiles`(覚えた位置があるとき)と `placeRows`(「整列」・初めて開いたとき)の2か所だけ。`grep TRAY_FILE_ID src/presentation` で、ほかに位置を決めている所が無いことを確かめた。サイドバーを自動で閉じているのも `ChangeRequestSidebarCloser` の1か所だけ。

### 検討した直し方(1440x900 での見積もり)

| 直し方 | 上級2 | 上級3 | 採否 |
| --- | --- | --- | --- |
| 依頼パネルをキャンバスの外に出す | — | — | 不要。依頼パネルは今もキャンバスの外(`EditorPanel`、`.app__body` の兄弟)にある。`canvasSize()` も `.canvas-column__flow` を測っているので、依頼パネルの幅は計算に入っている。「依頼パネルの下に隠れる」ように見えたのは、部品置き場がキャンバスの右端より外に出たため |
| 実装中の倍率の下限を 0.6 にする | 0.6 | 0.6 だが部品置き場が画面外 | 不採用。下限で止まると図の左上を基準に寄せるので、右端の部品置き場が見えないまま。図も収まらず、置き先のクラスが画面外になる。dnd-kit のドラッグ中は React Flow がパンしないので、画面外のクラスへは運べない |
| 部品置き場を図の下に置くだけ | 約0.42 | 約0.27(下限0.3で止まる) | これだけでは足りない |
| 課題サイドバーを閉じるだけ | 約0.6 | 約0.39 | これだけでは上級3が小さい |
| **サイドバーを閉じる + 部品置き場を図の下に置く** | 約0.79 | 約0.46 | **採用**。全体が収まり、部品置き場も置き先も同時に見える |

見積もりの計算は、キャンバスの幅を 600px(サイドバーあり)と約1040px(なし)、`autoViewport` の `padding: 0.1` で求めた。上級3の図の幅は、症状の座標から逆算して部品置き場を含め約2270px、含めず約1880px とした。

## 修正

`domain` / `application` / `infrastructure` は変更しない。新しい依存は足さない。倍率の下限(`CANVAS_MIN_ZOOM`・`DETAIL_ZOOM`)と `autoViewport` は変えない。

### 1. 変更依頼を始めたら、701px以上ならどの幅でも課題サイドバーを閉じる(presentation)

- `src/presentation/stage/StagePanel.tsx` の `ChangeRequestSidebarCloser`
  - `window.matchMedia('(min-width: 701px) and (max-width: 1399px)')` を `window.matchMedia('(min-width: 701px)')` にする
  - JSDoc の「701〜1399pxでは」を「701px以上では」に直し、1440px で上級2の倍率が 0.335 になったため上限を外した、と一言足す
- フォーカスの移動・読み上げ・終了後も閉じたまま、という #404 の動きは変えない
- 閉じるとキャンバスが広がるので、`FitViewOnResize`(#180)が合わせ直す。追加の処理は要らない

### 2. 部品置き場を、図の下の左端に置く(presentation)

- `src/presentation/canvas/keepFilePositions.ts` の `placeFiles`
  - 位置を覚えていない・ドロップ位置も無いファイルのうち、`id === TRAY_FILE_ID` のものだけ、既存のファイルの**下**に置く。x は `existingRects` の中で一番左の x、y は `existingRects` の中で一番下の辺 + `FILE_GAP`
  - 部品置き場は `right`(次の新しいファイルを置く右端)を更新しない。ほかの新しいファイルは今どおり右隣に並べる
  - `existingRects` が空のときは今どおり(レイアウトの位置のまま)
- `src/presentation/canvas/layoutCodebase.ts` の `placeRows`
  - 部品置き場(中身のあるもの。空なら今どおり `withoutEmptyTray` で消す)を `fileRows` に渡す前に取り除く。ほかのファイルを並べたあと、**最後の段として単独で、x = 0(図の左端)** に置く。y は今の段の積み方(`rowY`)どおり
  - 部品置き場の段には、層の帯(`bands`)を足さない。今は層のあるステージで部品置き場が「未分類」の段に入り、帯が出ているが、これも出なくなる
  - 部品置き場だけのコードベース(白紙設計の開始時)は、今と同じく (0, 0) に置かれる
- 白紙設計でも同じ `CodebaseCanvas` を使うので、「整列」すると部品置き場が図の下に移る。部品置き場は図の外の置き場なので、下にあるほうが一貫している。白紙設計のこの変化は受け入れる

ponytail: 部品置き場以外の新しいファイルの置き方(右隣)は変えない。図の折り返し(複数段への並べ替え)も足さない。

## テスト

先に失敗するテストを書く。

### Vitest(`src/presentation/canvas/keepFilePositions.test.ts` に追加)

- `placeFiles`: 覚えていない部品置き場(`id: TRAY_FILE_ID`)は、既存の矩形の一番左の x、一番下の辺 + `FILE_GAP` の y に置く
  - Arrange: 既存 `a`(x 20, y 80, 幅 180, 高さ 120)・`b`(x 260, y 40, 幅 180, 高さ 300)、覚えていない部品置き場
  - Assert: 部品置き場の位置が `{ x: 20, y: 400 }`(`40 + 300 + 60`)
- `placeFiles`: 部品置き場とほかの新しいファイル `c` が同時に来ても、`c` は今どおり既存の右隣(部品置き場の右ではない)に置かれる
- `placeFiles`: 位置を覚えている部品置き場は、その位置のまま(今の「知っているファイル」と同じ)

### Vitest(`src/presentation/canvas/layoutCodebase.test.ts` に追加)

- `layoutCodebase`: 依存の無いファイル `a`・`b` と中身のある部品置き場があるとき、部品置き場は x = 0 で、`a`・`b` のどちらの下の辺よりも下に置かれる
- `layoutCodebase`: 部品置き場だけのコードベースでは (0, 0) に置かれる
- `laneBands`: 層のあるステージで部品置き場があっても、「未分類」の帯が増えない

### E2E(新規 `e2e/change-request-canvas-fit.spec.ts`)

- `page.setViewportSize({ width: 1440, height: 900 })` で、上級3(`上級3: 会員ランクの割引をStrategyパターンへ組み替える`)を100点にする。「もう一度手で直す」があれば `releaseAllManualFixSites` で終え、`startChangeRequests`(`e2e/selectStage.ts`)で変更依頼を始める
  - 100点にする手順は、`e2e/refactor.spec.ts` の上級3のテストの操作(`addClassFromMenu` と「実装するインターフェースを設定」)を流用してよい。足りなければ、`refactor-blocks:drafts` に解答例のコードベースを入れて復元してもよい(`e2e/autosave.spec.ts` の要領)
- Assert(`expect.poll` で倍率と位置が落ち着くのを待つ)
  - 部品置き場のファイルノードの中のすべての部品(`[data-method-id]` のメソッドのチップ)の bounding box が、`.app__view:not([hidden]) .canvas-column__flow` の bounding box の内側に収まる
  - 同じく、すべてのファイルノード(`DiscountService` を含む)がキャンバスの内側に収まる
  - React Flow のビューポートの倍率(`.react-flow__viewport` の `transform` の `scale`)が 0.4 以上
  - 課題サイドバーが閉じている(`サイドバーを開く` ボタンが見える)
- 上級2も同じ手順で、倍率が 0.6 以上になり、部品(`charge()`)がキャンバスの内側に収まることを確かめる。手順の実装が重い場合は上級3だけでよい

### 既存の E2E の更新

- `e2e/preview.spec.ts` の「1800幅では変更依頼を始めても、サイドバーは開いたままで通知も出ない」は、新しい動きに合わせて「1800幅でも変更依頼を始めるとサイドバーが閉じ、閉じたことが読み上げられる」に書き換える(直前のコメント「広い画面(1400px以上)では…自動で閉じない」も消す)
- ほかに、変更依頼中に1400px以上で左サイドバーが開いていることや、部品置き場が右端にあることを前提にしている E2E があれば、同じく新しい動きに合わせる

## 受け入れ基準

1. 1440x900 で上級3を100点にし、「もう一度手で直す」を終えて「変更依頼に挑戦」を押すと、課題サイドバーが閉じる。部品置き場は図の下の左端に出て、すべての部品と `DiscountService` を含むすべてのファイルがキャンバスの内側に見える。倍率は 0.4 以上
2. 同じ手順で、上級2・上級8の倍率が 0.6 以上になり、部品がキャンバスの内側に見える
3. 上級3で「全体を表示」を押しても、全体がキャンバスに収まる(部品置き場も `DiscountService` も切れない)
4. 部品をドラッグして、見えているクラスへそのまま運べる(画面を動かさなくてよい)
5. 1366幅の #404 の動き(サイドバーが閉じ、フォーカスが開閉ボタンへ移り、読み上げられる)は今のまま
6. `npm run check` と `npm run test:e2e` が通る

## スコープ外

- 倍率の下限(`CANVAS_MIN_ZOOM` 0.3・`DETAIL_ZOOM` 0.6)と `autoViewport` の変更
- 依頼パネルの置き方・幅の変更(今もキャンバスの外にある)
- 部品置き場以外の新しいファイルの置き方(右隣に並べる)と、図の折り返し
- 変更依頼を終えたあとにサイドバーを開き直すこと(#404 と同じく、閉じたまま。手動で開ける)
- 700px以下(ドロワー)の動き
- 設計くらべ・プレビューのダイアログのキャンバス
