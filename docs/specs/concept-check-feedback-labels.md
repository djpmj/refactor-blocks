# concept-check-feedback-labels: 理解度チェックで不正解のとき、「正解です。」と読める解説を出さない

## 背景・目的

2026-10-17 にチュートリアル1の理解度チェックで、わざと不正解の「メソッドの数を増やすほど良い設計になるから」を選んで「答える」を押すと、次のように出た。

```
✗ 不正解(正解: 集計・計算・表示のどれを変えるときも、読む範囲をそのまとまりに絞れるから)
数を増やすこと自体は目的ではありません。意味のないまとまりで分けても、読みにくさは変わりません。
正解です。処理ごとに名前の付いたメソッドになっていれば、変えたい部分だけを読めばよくなります。
```

`concept-check` の仕様どおり、不正解のときは「選んだ選択肢の解説」と「正解の選択肢の解説」を続けて出している(`ConceptCheckPanel.tsx`)。
ところが正解の選択肢の解説はステージのデータで `正解です。…` から始まっているため、**見出しも無く続けて出ると、自分の答えが正解だったように読める**。
2つの段落がそれぞれ何の解説なのかも書かれていない。

## 変更対象ファイル一覧

| 種別 | パス | 層 | 役割 |
| --- | --- | --- | --- |
| 変更 | `src/presentation/stage/ConceptCheckPanel.tsx` | presentation | 2つの解説に見出しを付ける |
| 変更 | `src/infrastructure/stages/*.ts`(理解度チェックの `explanation`) | infrastructure | 正解の選択肢の解説の先頭の `正解です。` を消す |
| 変更 | ステージ定義のテスト(`stageCatalog.test.ts` など) | infrastructure | 解説が `正解です` で始まらないことを確かめる |
| 変更 | 理解度チェックの E2E | E2E | 新しい表示に合わせる |

## データ・型の変更

なし(文言だけ)。

## 表示の仕様

- 正解のとき: `✓ 正解` の下に `解説:` を付けて、選んだ選択肢の解説を出す
- 不正解のとき:
  - `✗ 不正解(正解: <正解の選択肢>)`(今のまま)
  - `あなたの答えについて:` + 選んだ選択肢の解説
  - `正解の理由:` + 正解の選択肢の解説
- 見出しは `<strong>` で、色だけに頼らない
- 正誤の結果は、今どおり判定行(`AnswerVerdict`)だけが伝える。解説の本文には正誤を書かない

## TDD対象の純粋関数

`domain` に新しいロジックは無い。

### ステージ定義のテスト(infrastructure)

- 全ステージの理解度チェックで、どの選択肢の `explanation` も `正解です` / `不正解です` で始まらない

## 受け入れ基準

1. チュートリアル1の理解度チェックで不正解を選ぶと、`あなたの答えについて:` と `正解の理由:` の見出しが出て、`正解です。` という文が出ない
2. 正解を選ぶと `✓ 正解` と `解説:` が出る
3. `npm run check` と `npm run test:e2e` が通る

## スコープ外

- 理解度チェックの問題・選択肢の内容の見直し
- 答え直しができるようにすること
