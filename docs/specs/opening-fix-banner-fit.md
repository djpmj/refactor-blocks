# opening-fix-banner-fit: 手直しの案内バナーが図に重なったり、キャンバスからはみ出したりしない

## 背景・目的

各ステージの最初に、キャンバスの上に出る案内バナー(「組み替える前に、まずこのコードのまま「…」を手で入れてみよう。…」と「実際に直してみる」ボタン、`OpeningFixBanner`)を実機で見ると、次の2つが起きる。

1. **キャンバスより広くなって両端が切れる**。バナーは `React Flow の Panel(top-center)` の上に `max-width: min(760px, calc(100vw - 32px))` で出るが、基準が画面の幅(`100vw`)でキャンバスの幅ではない。
   メソッドエディタ・左パネルを開くとキャンバスは660px前後になり、バナー(760px)は左右が50pxずつ切れる。文頭が欠け、右端の「実際に直してみる」ボタンも半分隠れる(初級1でメソッドをクリックして確認)
2. **図の上端に重なる**。自動の「全体を表示」はバナーの高さを考えないので、中級3などでは、バナーが先頭のファイルの上端(行数・警告アイコンの行)を覆う

案内を読ませたいのに、読めない・押せないことがある。バナーを、図と重ならない**通常の帯**にする(すでにある `前回の続きから再開しました` の帯と同じ作り)。

`domain` / `application` / `infrastructure` は変更しない。

## 動きの仕様

- バナーは、キャンバスの上端に接する帯(キャンバスの幅いっぱい)として、React Flow の外側に置く。バナーが出る間はキャンバスが帯の高さの分だけ低くなる
- 文が長いときは折り返す。「実際に直してみる」ボタンは、いつもキャンバスの中に完全に見える
- 帯は、出る条件(今の `OpeningFixBanner` の戻り値が `null` にならない条件)も、`data-testid="opening-fix-banner"`・`role="status"`・`data-tour="manual-fix-start"` も変えない
- バナーの出入りでキャンバスの大きさが変わると、`canvas-refit-on-resize`(キャンバスの大きさの変化での自動の合わせ直し)が働く。プレイヤーが図を動かしていないときだけ合わせ直す今の動きのまま
- 狭い画面(幅700px以下)の縦並びのスタイルは今のまま使える

## TDD対象

純粋なロジックの追加はない(`domain`/`application` は変更しない)。見た目と配置なので E2E で守る。

## 受け入れ基準

1. 初級1を開き、メソッドをクリックしてメソッドエディタを開いても、バナーの外接矩形がキャンバスの外接矩形の内側に収まり、「実際に直してみる」ボタンがクリックできる
2. 中級3を開いた直後、バナーのどの辺もファイルの箱・クラスの箱と重ならない(外接矩形が交わらない)
3. 幅1280pxと幅700px以下の両方で、1・2が成り立つ
4. 「実際に直してみる」を押すとバナーが消え、図の表示が不自然に飛ばない(消えた後も図がキャンバスの中に見える)
5. 変更依頼・操作ガイド(ツアー)の表示中は、今までどおりバナーが出ない
6. `npm run check` と `npm run test:e2e` が通る
