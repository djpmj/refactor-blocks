# 操作ガイド(「?」キーとボタンで開く、操作の一覧)

## 背景・目的

このゲームの操作は、見た目から気づきにくいものが多い。

- メソッド・フィールドを別のクラスへ**ドラッグ**で移す
- クラス・ファイル・メソッドを**右クリック**して、移動・追加・名前変更・継承元設定・削除をする
- クラス名・ファイル名・メソッド名を**ダブルクリック**してその場で名前を変える
- メソッドを**クリック**して、右側で処理を選んで抽出する
- **Ctrl+Z / Ctrl+Y** で取り消し・やり直し(いまはボタンのツールチップにしか書かれていない)
- 右側のサイドバーの境界を**ドラッグ、または矢印キー**で幅を変える

初めてのプレイヤーは、これらを自力で見つけるしかない。ステージの課題文は「何を直すか」であって「どう操作するか」ではない。
いつでも開ける**操作ガイド**を用意し、`?` キーまたはツールバーのボタンで開けるようにする。

## 見た目・内容の仕様

### 開き方・閉じ方

- ツールバー(「最初に戻す」などと同じ列)の末尾に、`操作ガイド`ボタン(`data-testid="operation-guide-open"`、`title="操作ガイド(?)"`)
- `?` キー(Shift+/)でも開く。**開いている間に `?` を押すと閉じる**
- 入力欄・選択欄・編集可能な要素にフォーカスがあるとき(`useUndoRedoShortcut` の `isEditingText` と同じ判定。共通化できるなら同じ関数を使う)は、`?` を文字入力として優先し、開かない
- リファクタリングのモードが表示中のときだけ `?` を受け付ける(設計くらべ・白紙設計では何もしない。`useUndoRedoShortcut(active)` と同じ扱い)
- 閉じるのは、`✕` ボタン、Esc、背景(ダイアログの外)クリックのいずれか(ネイティブ `dialog` の挙動に任せる。背景クリックは付けなくてもよい)
- 閉じたら、開く前にフォーカスがあった要素へ戻る(ネイティブ `dialog` の既定)

### 中身

見出しごとにまとめた定義リスト(`<dl>`)。定数 `OPERATION_GUIDE` を次の形にする。

```ts
export type GuideItem = { readonly operation: string; readonly description: string };
export type GuideSection = { readonly heading: string; readonly items: readonly GuideItem[] };
export const OPERATION_GUIDE: readonly GuideSection[];
```

最低限、次の内容を含める(文言は実装者が日本語で自然に整えてよい。**実際のUIの挙動と食い違う項目は載せない**。実装前に各操作を
コードかE2Eで確認し、実在しない操作は削る)。

1. **ブロックを動かす**: メソッド・フィールドを別のクラスへドラッグ / クラスを別のファイルへドラッグ / ドロップしたときの拒否理由は画面に出る
2. **右クリックメニュー**: ファイル・クラス・メソッドの上で右クリックすると、移動・追加・名前変更・継承元・実装先・削除ができる
3. **名前を変える**: クラス名・ファイル名・メソッド名をダブルクリックでその場編集(Enterで確定、Escで取り消し)
4. **処理を抽出する**: メソッドをクリックすると右側にエディタが開き、処理を選んで新しいメソッドに抽出できる
5. **取り消し・やり直し**: Ctrl+Z(Macは Cmd+Z)で取り消し、Ctrl+Y または Ctrl+Shift+Z でやり直し
6. **画面の操作**: キャンバスはドラッグで移動、ホイールでズーム。右サイドバーの境界はドラッグまたは←→キーで幅を変更
7. **このガイド**: `?` キーでこのガイドを開閉

「操作」の列は、キーは `<kbd>`、操作名は通常の文字で書く。

### ダイアログの体裁

- タイトル: `操作ガイド`(`aria-labelledby` で見出しに結びつける)
- 縦に長くなる場合、ダイアログ内でスクロールできる(ページ全体は動かさない)
- 狭い画面(幅 600px 程度)でも横にはみ出さない

## データ・型の変更

`GuideItem` / `GuideSection` / `OPERATION_GUIDE`(上記)のみ。ドメインの型は触らない。

## TDD対象の純粋関数

なし。

## 受け入れ基準

- `npm run check` が通る
- `npm run test:e2e` が通る(既存のドラッグ・右クリックなどのE2Eが、ボタンやキーの追加で壊れない)
- ツールバーの「操作ガイド」を押すとダイアログが開き、`OPERATION_GUIDE` の見出しと操作がすべて表示される
- `?` キーで開き、もう一度 `?` で閉じる。Esc・`✕` でも閉じる
- テキスト入力欄(メソッド名のその場編集・抽出の入力欄など)にフォーカスがあるとき、`?` を押しても開かない(入力できる)
- 設計くらべ・白紙設計のモードでは、`?` を押してもガイドが開かない
- 載せた操作が、実際のUIの挙動と一致している(削った項目があれば、PRの説明に書く)
- ダイアログはキーボードだけで閉じられる(Tab で `✕` にフォーカスでき、Esc でも閉じる)
- 既存の `Ctrl+Z` / `Ctrl+Y` が従来どおり動く

## スコープ外

- 初回起動時の自動表示・ステップごとのチュートリアル・ツアー
- 「見た」状態の保存(localStorage)
- ステージごとの操作ヒントの出し分け(ヒント機能 `stuck-player-hints` の領分)
- ショートカットのカスタマイズ・新しいショートカットの追加(`?` 以外は既存のものを載せるだけ)
- 白紙設計モード・設計くらべクイズ専用の操作説明
- 多言語対応
