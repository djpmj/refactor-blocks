# blank-design-tray-display: 白紙設計の部品置き場を、採点されるクラスのように見せない

## 背景・目的

2026-10-17 に白紙設計「白紙1: 注文と発送」を開いて、次の点が分かりにくかった。

1. 部品置き場(`TRAY_CLASS_ID` の `部品置き場` クラス)に、普通のクラスと同じ赤いバッジ `責務 4種類(上限 1)` と行数が出る。
   部品置き場は答え合わせの前に取り除かれ(`withoutTray`)採点されないのに、最初から違反しているように見える
2. 部品を1つ作ったクラスへ移すと、部品置き場から新しいクラスへ依存の矢印が引かれる。部品置き場はコードではないので、この矢印は意味が無い
3. 開いた直後、部品置き場のファイルの箱がキャンバスの左上の端にくっつき、枠の一部が切れて見える
4. 問題文(`blank-design__description` 相当)の文字が本文より小さく、読みにくい

## 変更対象ファイル一覧

| 種別 | パス | 層 | 役割 |
| --- | --- | --- | --- |
| 変更 | `src/presentation/canvas/ClassNode.tsx` | presentation | 部品置き場のクラスでは責務のバッジ・行数の警告を出さず、「部品置き場」と分かる見た目にする |
| 変更 | `src/presentation/canvas/FileNode.tsx` | presentation | 部品置き場のファイルでは行数・警告の印を出さない |

| 変更 | 白紙設計のキャンバスの初期表示(`BlankDesignView.tsx` など) | presentation | 開いたときに `fitView` の余白(padding)を取り、部品置き場の枠が切れないようにする |
| 変更 | 白紙設計の問題文のスタイル(`src/index.css`) | presentation | 問題文を本文と同じ大きさにする |
| 新規 | `e2e/blank-design-tray-display.spec.ts` | E2E | 下の受け入れ基準を確かめる |

`domain` / `application` / `infrastructure` は変更しない(部品置き場の判定は `domain/blank/tray.ts` の `TRAY_CLASS_ID` / `TRAY_FILE_ID` を使う)。

## データ・型の変更

なし。

## 見た目・動きの仕様

- 部品置き場のクラスの見出しは `部品置き場(あと N 個)` とし、責務のバッジ・行数・赤/黄の警告色を出さない。枠は点線にして、置き場であることを区別する
- 部品置き場のファイルの箱には、行数と ⚠️/⛔ の印を出さない
- 依存の矢印は、どちらかの端が部品置き場のクラスなら描かない
- 白紙設計のキャンバスを開いたとき・最初に戻したときは、ノード全体が余白付きで収まる(`fitView` の `padding` を他のキャンバスと同じにする)
- 白紙設計の問題文は `font-size` を本文と同じにする

## TDD対象の純粋関数

`domain` / `application` に新しいロジックは無い。依存の矢印から部品置き場を除く処理を `layoutCodebase.ts` の小さな関数に分けるなら、その関数にユニットテストを付ける
(部品置き場→クラスの依存は除く、クラス同士の依存は残す)。

## 受け入れ基準

1. 白紙1を開くと、部品置き場に `責務 4種類(上限 1)` のバッジも赤い色も出ず、見出しが `部品置き場(あと 7 個)` になっている
2. `placeOrder()` を余白へ移しても、部品置き場から新しいクラスへの矢印が出ない
3. 開いた直後、部品置き場のファイルの箱の枠がキャンバスの端で切れていない(箱の左端・上端がキャンバスの内側にある)
4. 答え合わせの点数は今と同じ
5. `npm run check` と `npm run test:e2e` が通る

## スコープ外

- 部品置き場を別のパネル(キャンバスの外)に出す作り直し
- 白紙設計の問題の追加
