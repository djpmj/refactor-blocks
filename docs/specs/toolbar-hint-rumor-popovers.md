# toolbar-hint-rumor-popovers: 「ヒント」と「気になるうわさ」をサイドバーからツールバーのポップオーバーへ移す

## 背景・目的

左サイドバー(`StagePanel` の `StageSidebar`、見出し「課題とヒント」)は、上から次の順に縦に並んでいる。

- 困っていること → クリア条件 → **気になるうわさ** → **ヒント(どこが問題? / 次の一手 / 動きで見る + ヒント一覧)** → 変更の痛み・実際に直してみる → どんなコード? → …

うわさとヒントが「クリア条件」と「変更の痛み」のあいだに挟まって縦に長くなる。そのため、課題を読む流れが途切れ、サイドバーが邪魔に感じられる。
どちらも「必要になったときに自分から見に行く」情報なので、常に見せる必要はない。

そこで、うわさとヒントをサイドバーから外し、キャンバスの上のツールバー(`ActionToolbar`)にボタンとして置く。押したときだけ小さなパネル(ポップオーバー)で開く。
左サイドバーは課題(困っていること・クリア条件・変更の痛み など)に専念させ、見出しも「課題」に変える。

## データ・型の変更

なし。

- ヒントの開封状態(`useStageHintState` の `count` / `problemRevealed`)は今のまま `StagePanelContent` で持つ。ポップオーバーを閉じても消えない
- ポップオーバーが開いているかどうかは画面の状態(`useState`)で持ち、保存しない
- ヒントのポップオーバーは `ReferenceMenu` からも開くので、`StagePanelContent` で持つ。うわさのポップオーバーは `RumorPopover` の中で持つ

## TDD対象の純粋関数

なし(`domain` / `application` の新しいロジックは無い。表示の移動だけ)。
動きは E2E で守る。

## 見た目・動きの仕様

### ツールバーの並び

左から次の順にする。

1. 変更依頼に挑戦
2. 元に戻す
3. やり直し
4. 最初に戻す
5. 参考・答え ▾
6. **ヒント ▾**(新規、`data-testid="hint-popover-button"`)
7. **うわさ(N) ▾**(新規、`data-testid="rumor-popover-button"`)
8. 操作ガイド

- 「うわさ」の N は、そのステージでうわさ(`rumor`)を持つ変更依頼の件数とする。数え方は今の `RumorList` と同じで、`rumoredRequests(stage)` のうち `rumor` があるもの
- 件数が0のステージでは、「うわさ」ボタン自体を出さない
- 変更依頼に挑戦している間(`changeSession !== null`)は、「ヒント ▾」「うわさ ▾」をどちらも無効にする。開いていたら閉じる
  - 今はこの間、ヒントのボタンが無効になり、うわさは表示されない。それに揃える

### ポップオーバー共通(`ReferenceMenu` に揃える)

- ボタンには `aria-haspopup="dialog"`・`aria-expanded`・`aria-controls` を付ける。押すたびに開閉する
- パネルは `role="dialog"`(モーダルではない)とし、`aria-label` はそれぞれ「ヒント」「気になるうわさ」にする。ボタンの下・右端揃えで開く
- 開いたら、パネルの中で最初の有効なボタンにフォーカスする。ボタンが無いうわさのパネルではパネル自体(`tabIndex={-1}`)にフォーカスする
- 閉じ方は次の3つ。
  - Esc で閉じ、ボタンにフォーカスを戻す
  - パネルとボタンの外側をクリックすると閉じる
  - もう一度ボタンを押すと閉じる
- パネルの中は Tab で順に移動する(メニューではないので ↑↓ の移動は付けない)
- 同時に開くのは1つだけにする。ヒント・うわさ・参考・答えのどれかを開いたら、ほかは閉じる(外側クリックの動きでそうなればよい)
- 幅は `min(360px, calc(100vw - 32px))` まで、高さは画面に収まらなければパネルの中をスクロールさせる。狭い画面(700px以下)でも横にはみ出さない

### ヒントのポップオーバー(`HintPopover`、`data-testid="hint-popover"`)

- 中身は、今のサイドバーの「ヒント」セクションをそのまま移す
  - ① どこが問題?(`ProblemHint`)
  - ② 次の一手(`HintButton`)
  - ③ 動きで見る(`GhostHintButton`)
  - ヒント一覧(`HintList`。方針の見出し `hint-phase` を含む)
- 各ボタンの有効・無効の条件、`title`、`data-testid` は変えない
- **自動で閉じる**: 次の2つを押したら、ポップオーバーを閉じる(キャンバス上の光る場所や動きを隠さないため)
  - ヒント一覧の「キャンバスで見る」
  - 「動きで見る」
- 「どこが問題?」「次の一手」は、出てくる文章を読むので開いたままにする
- 閉じて開き直しても、開いたヒント(どこが問題?の説明文・ヒント一覧)はそのまま残る。ステージを切り替えたら今と同じく最初からになる

### 手が止まったときの脈打つ演出

- 今は「どこが問題?」ボタンに `ghost-hint-button--idle` を付けて脈打たせている。これを、ツールバーの「ヒント ▾」ボタンに付けるように変える
- 条件は今と同じにする: `useIdle(!無効 && !problemRevealed && score.total < 100, codebase, stageId)`
- そのうえで、ポップオーバーが開いている間は付けない
- ポップオーバーの中の「どこが問題?」ボタンは、もう脈打たない
- `prefers-reduced-motion` では今と同じく動かさない(既存の CSS のまま)

### うわさのポップオーバー(`RumorPopover`、`data-testid="rumor-popover"`)

- 中身は今の `RumorList` をそのまま移す
  - 見出し「気になるうわさ」と説明文
  - 一覧。各項目の `data-testid="rumor-<id>"` は変えない
  - 外側の `data-testid="rumor-list"` も残す
- ストーリーがオフのときに「〜から」を出さないのも今のまま
- 変更依頼の結果に出る「うわさが本当になった」(`rumor-came-true`)・`rumor-payoff` は、別の画面なので変えない

### 参考・答えの「ヒントを見る」

- 答えの前の確認ダイアログで「ヒントを見る」を押したら、確認ダイアログを閉じる
- 続けてヒントのポップオーバーを開き、今と同じく次のヒントを1つ開く
  - まだ「どこが問題?」を見ていなければ、それを開く
  - 見ていれば「次の一手」を1つ開く
- サイドバーは開かない(今はサイドバーを開いている)
- フォーカスはヒントのポップオーバーへ移す

### 左サイドバー

- 「気になるうわさ」と「ヒント」のセクションを取り除く。残りの並びと表示条件は変えない
- 見出し(`sidebar__title`)を「課題とヒント」から「課題」に変える。あわせて次の文言も「課題」に揃える
  - `aside` の `aria-label`(`課題`)
  - 幅変更ハンドルの `aria-label`(`課題の幅を変更`)
  - 狭い画面の背景ボタンの `aria-label`(`課題の外側をタップして閉じる`)
- ツアー1手目(`#stage-sidebar`、「ここに課題が出ます。…」)は、文言も対象もそのままでよい

## 受け入れ基準

- [ ] ツールバーが「変更依頼に挑戦・元に戻す・やり直し・最初に戻す・参考・答え ▾・ヒント ▾・うわさ(N) ▾・操作ガイド」の順に並ぶ
- [ ] 左サイドバーにヒント(`hint-problem` など)とうわさ(`rumor-list`)が無い。見出しは「課題」で、`aside` の名前も「課題」
- [ ] 「ヒント ▾」を押すと `hint-popover` が開き、どこが問題?・次の一手・動きで見る・ヒント一覧が今と同じ条件で使える
- [ ] ヒントのポップオーバーで「キャンバスで見る」「動きで見る」を押すと、ポップオーバーが閉じる。キャンバスのハイライト・動きは今と同じく出る
- [ ] 「どこが問題?」「次の一手」を押してもポップオーバーは閉じない。閉じて開き直しても、開いたヒントが残っている
- [ ] 「うわさ(N) ▾」の N が、そのステージのうわさの件数と一致する(チュートリアル1なら2)。うわさの無いステージでは、ボタンが出ない
- [ ] うわさのポップオーバーで、`rumor-<id>` に今と同じ文言が出る。ストーリーがオフのときは「〜から」が出ない
- [ ] どちらのポップオーバーも、Esc で閉じてボタンにフォーカスが戻る。外側クリック・ボタンの再押下でも閉じる。開くと中の最初の有効なボタン(うわさはパネル)にフォーカスが移る
- [ ] 変更依頼に挑戦している間は「ヒント ▾」「うわさ ▾」が無効になる。開いていたものは閉じる
- [ ] 手が止まると「ヒント ▾」ボタンが `ghost-hint-button--idle` で脈打つ。ポップオーバーを開いている間と、「どこが問題?」を開いたあとは脈打たない
- [ ] 参考・答えの確認ダイアログで「ヒントを見る」を押すと、ヒントのポップオーバーが開いて次のヒントが1つ開く。サイドバーは開かない
- [ ] 狭い画面(375px幅)で、ポップオーバーが横にはみ出さずに表示・操作できる
- [ ] 既存の E2E を新しい手順に直したうえで、`npm run check` と `npm run test:e2e` が通る
- [ ] `e2e/toolbar-hint-rumor-popovers.spec.ts` で、上の開閉・自動で閉じる動き・件数・脈打つ演出を確かめている

## スコープ外

- ヒントの中身・段階・有効になる条件の変更
- うわさの文言・件数の決め方の変更。未読の印(●)は付けない(件数バッジだけ)
- ツアーの手順の追加・変更(ヒントやうわさのボタンを案内する手順は足さない)
- 右のメソッドエディタ側への移動、ポップオーバー以外の配置(ドロワー・タブなど)
- サイドバーに残る他のセクション(変更の痛み・どんなコード? など)の並び替えや折りたたみ
- ポップオーバーの開閉状態の保存
