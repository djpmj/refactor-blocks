# move-class-to-new-file-menu: 右クリックメニューから、クラスを新しいファイルへ移せるようにする

## 背景・目的

2026-10-17 に中級2「何でも入った1つのファイル」(1ファイルに3クラス。課題はファイルを分けること)で、クラスを右クリックしても
**新しいファイルへ移す項目が無かった**。「別のファイルへ移動」は**既存の**別ファイルが候補のときだけ出る(`move-class-via-context-menu`)ので、
ファイルが1つしかないこのステージでは、クラスのヘッダーを余白へドラッグする以外に分ける方法が無い。

- マウスでも、ドラッグで余白へ落とせば新しいファイルになることに気付きにくい
- キーボードだけで遊ぶ人は、最初のファイル分けができない(ponytail の「手を抜かないもの」のアクセシビリティ)

`move-class-via-context-menu` では「新しいファイルへ移動」(`moveClassToNewFile`)のメニュー化を**後回し**にしていた。今回これを入れる。

## 変更対象ファイル一覧

| 種別 | パス | 層 | 役割 |
| --- | --- | --- | --- |

`domain` / `application` は変更しない(既存の `moveClassToNewFileUseCase` とストアの `moveClassToNewFile` を呼ぶだけ)。

## データ・型の変更

なし。

## 振る舞い

- クラスを右クリックしたメニューの「クラス <名前>」の欄に、`新しいファイルへ移動` を足す(「別のファイルへ移動」のすぐ下)
  - サブメニューではなく、押せばすぐ移す項目にする
  - そのクラスがファイルの中の唯一のクラスのときは出さない(移しても形が変わらないため)
- 押すと `moveClassToNewFile(classId)` を呼ぶ。新しいファイルの箱は、元のファイルの右隣(重ならない位置)に置く。置き方はドラッグで余白へ落としたときの既定の配置と同じ規則を使う
- 押したあとは、移したクラスのヘッダー(`role="button"` の要素)へフォーカスを移す
- 元に戻す(Ctrl+Z)で1手として戻る
- 冒頭の手直しのロック中・変更依頼の挑戦中は、ほかの移動と同じく今の規則で止める

## TDD対象の純粋関数

`domain` / `application` に新しいロジックは無い(既存の `moveClassToNewFile` のテストがある)。
メニューに出すかどうか(「ファイルの唯一のクラスではない」)の判定は1行なので、E2E で確かめる。

## 受け入れ基準

1. 中級2で `ShippingService` を右クリックすると `新しいファイルへ移動` が出て、押すと `ShippingService` が新しいファイルの箱に移る
2. 1のあと、`ShippingService` のヘッダーにフォーカスがある
3. `ShippingService` にフォーカスして Shift+F10(またはメニューキー)でメニューを開き、Tab/Enter だけで1と同じ操作ができる
4. ファイルに1クラスしかないとき(1のあとの `ShippingService` を右クリック)は、`新しいファイルへ移動` が出ない
5. Ctrl+Z で移動前に戻る
6. `npm run check` と `npm run test:e2e` が通る

## スコープ外

- メソッドを新しいクラスへ移す項目のメニュー化(既にあるものは変えない)
- ファイル名(パス)の変更
