# 左サイドバーの開閉ボタンが、サイドバーのスクロールバーに重ならないようにする

## 背景・目的

左の「課題とヒント」サイドバーの開閉ボタン(`«` / `»`、`.sidebar-toggle`)は、`sidebar-toggle-position` でサイドバーの右端の境界に置いた。
ただし位置を `left: 250px`(サイドバー幅260pxより10px内側)にしており、ボタンの左10pxがサイドバーの右端に**重なる**。
サイドバーは内容が長くて縦スクロールが出ると右端にスクロールバーが出るため、ボタンがスクロールバーの上端(▲の矢印)を隠し、
スクロールバーが途中で切れて見える。境界線の位置も、どちらのものか分かりにくい。

ボタンを、サイドバーの**外側**(右の境界線の外、キャンバス側)に、境界線にぴったり接する形で置き直す。

## 変更対象ファイル一覧

### 変更

- `src/index.css`(presentation)
  - `.app__body--sidebar-open > .sidebar-toggle { left: 250px }` を `left: 260px`(= `.sidebar` の幅)にする。
    ボタンの左端がサイドバーの右端と一致し、サイドバーの内側には1pxも食い込まない
  - 狭い画面用の既存の上書き `.app__body--sidebar-open > .sidebar-toggle { left: calc(40vw - 10px) }` も `left: 40vw` に直す
    (`.sidebar` の幅が `min(260px, 40vw)` のため、ここでもサイドバーの右端と一致させる)
  - ボタンの `border-left: 0`・右側だけの角丸・縦位置(`top: 8px`)・`z-index`・ホバー/フォーカスの見た目は変えない。
    左の境界線はサイドバーの `border-right` がそのまま見える
  - 閉じているときの位置(`left: 0`)は変えない
  - 色の直書きはしない(既存の `var(--surface)` / `var(--border)` / `var(--accent)` のまま)
- `e2e/sidebar-toggle.spec.ts`: 既存ケースに追記する(新規ファイルは作らない)

## データ・型の変更

なし。

## TDD対象の純粋関数

なし(CSSのみの変更)。位置はE2Eで守る。

## 受け入れ基準

- `npm run check` と `npm run test:e2e` が通る。既存の `sidebar-toggle.spec.ts` のケース(開閉・位置が境界の近く)が壊れない
- サイドバーが開いているとき、開閉ボタンの左端(`boundingBox().x`)が、サイドバーの右端(`sidebar.x + sidebar.width`)以上である
  (サイドバーに重ならない。誤差は1px以内)。差は 0〜2px 程度で、境界にぴったり接している
- 内容が長くてスクロールバーが出るステージ(例: 上級3)で、サイドバーのスクロールバー全体(上端の▲を含む)が、ボタンに隠れず見える
- 狭い画面(画面幅の40%がサイドバー幅になる場合)でも、ボタンがサイドバーの右端に接していて、重ならない
- 閉じているときは、従来どおりボタンは画面左端(`x` が 40px 未満)に出て、押して開ける
- ライト・ダークどちらでもボタンが見える。Tab・Enter/Space で開閉できる(フォーカスリングを消さない)

## 他のIssueとの関係

`resizable-left-sidebar`(Issue #98)は、`.sidebar` の幅とこのボタンの位置を CSS カスタムプロパティ `--sidebar-width` で追従させる。
このIssueのほうを先にマージする場合は、#98 側が `left: calc(var(--sidebar-width, 260px) - 10px)` と書いている部分を
`left: var(--sidebar-width, 260px)` にそろえる(後から入れるほうが rebase で、重ならない位置を保つ)。
