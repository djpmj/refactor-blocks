# 押せるボタン・動かせるブロックを見た目で伝える

## 背景・目的

画面には、点数、サイドバー、メソッドエディタ、キャンバスと要素が多く、プレイヤーは「今どこを触ればいいか」に気づきにくい。特に次の2点が分かりにくい。

1. メソッドエディタの「選んだ処理をメソッドとして抽出」ボタン(`MethodEditor.tsx`)は、処理を1つも選んでいなくても押せる見た目のまま。押しても何も起きないか、エラーになるだけで、「処理を選んでから押す」という順番が伝わらない。
2. キャンバスのメソッド(`MethodChip.tsx`)は、カーソルが `grab` になるだけで、「ドラッグで別のクラスへ移せる」「ダブルクリックで名前を変えられる」ことが見た目から分からない。操作ガイド(`?` キー)を開かないと知る手段がない。

そこで、**押せないときは押せない見た目、押せるようになったら目立つ色**にし、**キャンバスのブロックにはホバーで操作の説明**を出す。

## ponytailチェック

1. YAGNI: 独自のツールチップ部品は作らない。ブラウザ標準の `title` 属性で足りる(遅延表示・タッチ非対応は許容。必要になったら別仕様)。
2. 既存の再利用: 強調色はツールバーの `toolbar__primary`(`--accent`)と同じ配色を使う。抽出できるかどうかの判定は、`extractMethod` の検証と同じ条件(処理が1つ以上選ばれている・名前が空でない)を画面側でも見るだけにし、ドメインには手を入れない。
3. 新しい依存は足さない。

## 仕様

### 抽出ボタン(`MethodEditorBody`)

- 押せる条件: 選んだ処理が1つ以上あり、かつ新しいメソッド名(`newName.trim()`)が空でない。
- 押せないとき: `disabled` にし、通常の(目立たない)見た目にする。ボタンの近くに `処理を1つ以上選ぶと押せます` という短い説明を出し、ボタンの `aria-describedby` で結び付ける(読み上げでも理由が分かるように)。名前が空のときは `メソッド名を入れると押せます` にする。
- 押せるとき: `button--primary`(強調色)にする。説明文は出さない。
- 処理をすべて選んだときなど、ドメイン側の検証で失敗するケースは今までどおりエラーのトーストで知らせる(画面側で条件を増やさない)。

### ホバーの説明(`title`)

| 要素 | 通常時の `title` | 手で直すシミュレーション中 |
| --- | --- | --- |
| メソッド(`MethodChip`) | `クリックで中身を表示 / ドラッグで別のクラスへ移動 / ダブルクリックで名前を変更` | `クリックで「直した」印を付け外し` |
| フィールド(`FieldChip`) | `クリックで説明を表示 / ドラッグで別のクラスへ移動` | 変更なし |
| クラス名の見出し(`ClassNode`) | `ドラッグで別のファイルへ移動 / ダブルクリックで名前を変更` | 変更なし |

- 既存の `aria-label` や `data-testid` は変えない。
- 文言は1か所の定数にまとめ、操作ガイド(`OPERATION_GUIDE`)と言い回しを揃える(実際の操作と違うことを書かない。クラス名のダブルクリック編集など、今できない操作は書かない。実装時に実際の操作を確認する)。

## 受け入れ基準

1. `npm run check` が通る。
2. メソッドを選んだ直後(処理を1つも選んでいない状態)は、抽出ボタンが押せず、`処理を1つ以上選ぶと押せます` が表示される。
3. 処理を1つ選ぶと、抽出ボタンが押せるようになり強調色に変わる。選択を外すと元に戻る。
4. メソッド名を空にすると、抽出ボタンが押せなくなり `メソッド名を入れると押せます` が表示される。
5. キャンバスのメソッド・フィールド・クラス名の見出しに、上表の `title` が付いている。手で直すシミュレーション中はメソッドの `title` が切り替わる。
6. E2E(`e2e/action-affordance.spec.ts`): 2〜5を確認する。既存のE2E(抽出・ドラッグの操作)が無変更で通る。
7. `npm run test:e2e` が通る。

## スコープ外

- 独自のツールチップ部品(遅延なし表示・タッチ端末での表示)。
- 抽出ボタン以外のボタンの非活性化の見直し(統合・呼び出し元へ戻す・空実装の削除は、もともと使えるときだけ表示している)。
- 初回のスポットライト・ガイド(別仕様 `first-visit-tour.md`)。
- ヒントからキャンバスのブロックを光らせる機能(別仕様 `hint-highlight.md`)。
