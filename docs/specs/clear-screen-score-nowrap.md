# clear-screen-score-nowrap: クリア画面の「100点」が円の中で2行に折り返す

小さな不具合修正。新しい機能や設計判断はない。

## 症状

プレイテスター3人がそれぞれ別に再現した。どのステージでも100点にすると、クリア画面(`ClearScreen`)が開く。スコアの円の中で「100」と「点」が2行に折り返し、円いっぱいに詰まって見える。

- 円の内側の要素 `[data-testid="clear-screen-score"]` は、幅148pxに対して高さが174pxになっている(`white-space: normal`)
- カウントアップ途中の「1点」「21点」や、2桁の「82点」では1行に収まる。3桁の「100点」のときだけ崩れる

## 原因

`src/index.css` の `.clear-screen__ring span` の指定が原因。

- 文字の大きさは `font-size: clamp(34px, 7vw, 60px)`。幅1280pxの画面では上限の60pxになる
- 内側の円の幅は外側のリング(`clamp(130px, 24vw, 190px)` → 190px)の78%で、約148pxになる
- 太さ800の60pxで「100点」を書くと、数字3文字(1文字あたり約0.6em)と「点」(1em)で約2.8em、つまり約168pxになり、148pxに入りきらない。`white-space` を指定していないので「点」の前で折り返し、`aspect-ratio: 1` の円が縦に伸びる

ほかに直す場所はない。`clear-screen-score` を使っているのは `src/presentation/stage/ClearScreen.tsx` だけで、`.clear-screen__ring span` を指定しているのも `src/index.css` のこの1行だけ。

## 修正

`src/index.css`(presentation)の `.clear-screen__ring span` の1行だけを変える。TSX(DOM構造)は変えない。

- `white-space: nowrap;` を足す
- `font-size` を `clamp(34px, 7vw, 60px)` から `clamp(28px, 6vw, 48px)` にする

文字の大きさを約2.8em ≤ 内側の円の幅(リングの78%)にするための値。

| 画面の幅 | 内側の円 | 文字の大きさ | 「100点」の幅(約2.8em) |
|---|---|---|---|
| 1280px(上限) | 約148px | 48px | 約134px |
| 24vw〜6vw の範囲 | 約18.7vw | 6vw | 約16.8vw |
| 狭い画面(下限) | 約101px | 28px | 約78px |

どの幅でも1行で円の内側に収まる。

- 方法の選び方: 候補は「『点』だけを別の要素にして小さくする」「リングを大きくする」「全体の文字を小さくする」の3つ。いちばん小さい変更として、全体の文字を小さくする方法を選んだ
  - 「点」を `<small>` などに分けると、`display: grid` の `span` の中で別のグリッド項目になり、数字と別の行に並んでしまう。そのため、さらに入れ子の要素が要る
  - リングを大きくすると、クリア画面全体の縦の並びが変わる
- 2桁の点数(カウントアップの途中)も同じ割合で少し小さくなる。それは受け入れる
- `data-testid="clear-screen-score"` のテキストは `100点` のままなので、既存のE2Eの `toHaveText('100点')` はそのまま通る

## テスト

TDD対象(Vitest)はなし。CSSだけの修正のため。

E2E は `e2e/clear-screen.spec.ts` に1本足し、修正前に失敗することを確かめてから直す。

- テスト名: `100点のスコアは円の中で1行に収まる`
- 既存の `clearTutorial1(page)` で100点にする。カウントアップが終わるのを `await expect(page.getByTestId('clear-screen-score')).toHaveText('100点')` で待つ
- `page.getByTestId('clear-screen-score').evaluate(...)` で次の3つを取り出し、それぞれ確かめる
  1. **1行であること**: `document.createRange()` で要素の中身を選び(`selectNodeContents`)、`getClientRects()` で文字の矩形を取る。どの矩形の `top` も、最初の矩形との差が1px以内であること。2行に折り返すと「点」の `top` が下にずれるので失敗する
  2. **円が縦に伸びていないこと**: `getBoundingClientRect()` で `height <= width + 1` であること。修正前は 174 > 148 なので失敗する
  3. **横にはみ出していないこと**: `scrollWidth <= clientWidth` であること。`nowrap` だけを足して文字を小さくし忘れた場合に、このチェックで失敗する
- Playwright の既定の画面(1280×720)で走らせる。文字が上限の48pxになる、いちばん厳しい幅なので、これで足りる

## 受け入れ基準

1. チュートリアル1で100点にしてクリア画面を開くと、円の中に「100点」が1行で表示される。円は縦に伸びず、文字が円の外にはみ出さない
2. カウントアップの途中(1桁・2桁)でも1行で、円の形が崩れない
3. 狭い画面(幅390px程度)でもクリア画面の「100点」が1行で円の内側に収まる(目視で確認)
4. 追加したE2Eが修正前は失敗し、修正後は通る
5. `npm run check` と `npm run test:e2e` が通る

## スコープ外

- 「点」だけを小さくするなど、TSXの構造を変えること
- リングの大きさ、色、アニメーション(`clear-glow`・カウントアップ)を変えること
- クリア画面のほかの文字の大きさ(見出し、eyebrow、選択肢)を変えること
- ヘッダーのスコア表示など、クリア画面以外の点数表示
