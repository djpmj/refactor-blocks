# sidebar-flow-visibility: 左パネルで「次にやること」を見失わないようにする

## 背景・目的

2026-10-17 にストーリーどおり第1章→第2章→第3章と遊んで、左パネル(`#stage-sidebar`、`StagePanel`)で次にやることを見失う場面が続いた。
左パネルは「ストーリー・困っていること・クリア条件・うわさ・ヒント・変更の痛みカード・手直し・どんなコード?・理解度チェック・章の結び」と縦に長く(実測で表示の高さの約2倍)、

1. **章を進めてもスクロール位置が前の章のまま**: 第1章の下の方までスクロールして「次の章へ」を押すと、第2章でも `scrollTop` が 683px のまま残り、
   ストーリーとクリア条件が隠れた状態で始まる
2. **段階が進んだことに気付けない**: 100点になって「もう一度手で直す」段階(`closing-fix`)に入ったり、手直しに正解して「なぜ分けるのか」(`change-request`)に進んだりしても、
   そのカードが画面外にあると何も起きていないように見える。100点の「第1章 おわり / 次の章へ」も最下部で見落としやすい
3. **章の結びの依頼が宙に浮く**: `StoryOutro` は依頼のタイトル(例: `前年同月比も出して`)を常に出すが、「依頼を受ける」ボタンは `stageStep` が `change-request` のときだけ出る。
   手直しが終わっていないとタイトルだけが残り、すぐ下の「次の章へ」と並ぶので、次の章がその依頼の話のように読める(実際の第2章は placeOrder の話)

## 変更対象ファイル一覧

| 種別 | パス | 層 | 役割 |
| --- | --- | --- | --- |
| 変更 | `src/presentation/stage/StagePanel.tsx` | presentation | ステージが変わったら左パネルを先頭へ戻す。同じステージで段階が進んだら変更の痛みカードを画面内へスクロールする |
| 変更 | `src/presentation/stage/StoryOutro.tsx` | presentation | 依頼のタイトルは「依頼を受ける」ボタンと一緒のときだけ出す |
| 変更 | 上の表示を確かめている既存の E2E(`story-outro` / `story-request-title` を見ているもの) | E2E | 新しい表示に合わせる |
| 新規 | `e2e/sidebar-flow-visibility.spec.ts` | E2E | 下の受け入れ基準を確かめる |

`domain` / `application` / `infrastructure` は変更しない。

## データ・型の変更

なし。

## 見た目・動きの仕様

### 1. ステージが変わったら先頭へ

- `stage.id` が変わったら、`#stage-sidebar` の `scrollTop` を 0 にする(ステージ一覧・「次の章へ」・おすすめのどれから切り替えても同じ)
- 左パネルを閉じているとき(`hidden`)も、次に開いたときに先頭から見える

### 2. 同じステージで段階が進んだらカードを見せる

- `stageStep`(`domain/change/stageStep.ts`)の値が、**同じステージのまま**次のように変わったとき、変更の痛みカード(`ChangePainCard` の `section.change-pain`)を
  `scrollIntoView({ block: 'nearest' })` で左パネルの中へスクロールする(`prefers-reduced-motion: reduce` でなければ `behavior: 'smooth'`)
  - `opening-fix` → `refactor`
  - `refactor` → `closing-fix`(100点になった)
  - `closing-fix` → `change-request`(手直しに正解した)
- ステージを開いた直後(初回の描画)と、ステージの切り替えではスクロールしない(1が優先)
- 段階が戻ったとき(元に戻すで100点を下回ったなど)はスクロールしない
- 手直しの最中(`manualFix !== null`)はスクロールしない(`manual-fix-clarity` の手直しパネルのスクロールと取り合わないため)
- `change-request` に進んだときは、カードのすぐ下に続く章の結び(`StoryOutro`)も見えやすくなるよう、カードの先頭が見える位置に合わせる(`block: 'start'`)

### 3. 章の結びの依頼

- `StoryOutro` の依頼のタイトル(`story-request-title`)は、「依頼を受ける」ボタン(`story-accept`)を出すとき(`step === 'change-request'`)だけ出す
- それ以外は、章の結びの文(`outro`)と「次の章へ」だけを出す

## TDD対象の純粋関数

`domain` / `application` に新しいロジックは無い。段階が「進んだ」かの判定は、`StagePanel.tsx` の中に小さな関数として置く(例: `advancedStep(previous, next)`)。
表示とスクロールの変更なので E2E で確かめる。

## 受け入れ基準

1. チュートリアル1で左パネルを一番下までスクロールし、100点にして「次の章へ」を押すと、チュートリアル2の左パネルが先頭(ストーリーのカード)から表示される
2. ステージ一覧から別のステージを選んだときも、左パネルが先頭から表示される
3. 画面の高さが 700px のとき、チュートリアル2で冒頭の手直しを終えて100点にすると、「もし、この変更が来たら?(もう一度)」のカードが画面内に見えている
4. 3のあと手直しに正解すると、「なぜ分けるのか」のカードが画面内に見えている
5. 手直しを終えていない状態で100点にすると、章の結びに依頼のタイトル(`story-request-title`)が出ない。手直しに正解すると、タイトルと「依頼を受ける」が一緒に出る
6. `npm run check` と `npm run test:e2e` が通る

## スコープ外

- 左パネルの並び順や、カードの折りたたみ方の見直し
- 100点になったときのキャンバス側の演出の追加
- 手直しパネル自体のスクロール(`manual-fix-clarity` で扱う)
