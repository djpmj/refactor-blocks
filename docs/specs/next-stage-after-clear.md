# next-stage-after-clear: ステージを100点にしたあと、次のステージへ進む入口を出す

## 背景・目的

ステージを100点にしたとき、ストーリーがオンなら「第1章 おわり」のカード(`StoryOutro`)に「次の章へ」ボタンが出る。
しかし、ストーリーをオフにしている(ヘッダーの「ストーリー」で切り替え)と、100点の画面に**次へ進む入口が何も出ない**。
点数のリングが100点になり「減点なし」と出るだけで、次に何をすればよいのかが分からず、ステージ一覧を自分で開いて探すことになる。
ステージ一覧には「次のおすすめ」が出る(`recommendNextStage`)ので、その入口を100点の画面にも出す。

## 変更対象ファイル一覧

| 種別 | パス | 層 | 役割 |
| --- | --- | --- | --- |
| 新規 | `src/presentation/stage/NextStageCard.tsx` | presentation | 100点のとき、次のおすすめのステージへ進むカード |
| 変更 | `src/presentation/stage/StagePanel.tsx` | presentation | `StoryOutro` の隣に `NextStageCard` を置く(`StageSidebar` の中) |
| 変更 | `src/index.css` | presentation | カードのスタイル(`story-card` と同じ見た目を使い回す) |
| 新規 | `e2e/next-stage-after-clear.spec.ts` | E2E | 受け入れ基準を確かめる |

`domain` は変更しない(既存の `recommendNextStage(stages, progress)` を使う)。新しい依存は足さない。

## 動きの仕様

- 出る条件: 採点の対象のコードが100点(`StoryOutro` の `perfect` と同じ判定)で、かつ **`StoryOutro` が出ていない**(ストーリーがオフ、またはそのステージの章が無い)とき
  - 変更依頼の実装中(`changeSession !== null`)・手直し中は出さない(今の `StoryOutro` と同じ)
- 内容:
  - 次のおすすめがあるとき: 見出し `ステージクリア`、文 `次のおすすめ: <ステージ名>`、ボタン `次のステージへ`(押すと `selectStage(次のおすすめのID)`)
  - 次のおすすめが無いとき(全ステージをクリア済み): 見出し `ステージクリア`、文 `全ステージをクリアしました`(ボタンなし)
- 次のおすすめが今のステージ自身になることはない(今のステージは自己ベスト100で記録される。記録が追いつく前の一瞬に自分自身が出るなら、そのときはカードを出さない)
- 変更依頼(`変更依頼に挑戦`)への導線は変えない。カードは「次へ進む」だけを案内し、変更依頼の案内を隠さない(`ChangeRequest` の領域より下に置く)
- `data-testid="next-stage-card"`、ボタンは `data-testid="next-stage-go"`
- `role` は付けない(静的な案内。点数の読み上げは `score-announcement` がすでにしている)

## TDD対象

純粋なロジックの追加はない(`recommendNextStage` は既存・テスト済み)。表示と操作なので E2E で守る。

## 受け入れ基準

1. ストーリーをオフにして、チュートリアル1を100点にすると、左パネルに「ステージクリア / 次のおすすめ: チュートリアル2: 太った placeOrder / 次のステージへ」が出る。「次のステージへ」を押すとチュートリアル2が開く
2. ストーリーがオンのときは、今までどおり「第1章 おわり / 次の章へ」だけが出る(新しいカードは出ない)
3. 100点でないときは、新しいカードは出ない
4. 全ステージをクリア済みのとき、「全ステージをクリアしました」が出る
5. `npm run check` と `npm run test:e2e` が通る

## スコープ外

- ステージ一覧(ロードマップ)の変更
- ストーリーがオンのときの「次の章へ」の挙動の変更
- クリア時の演出(紙吹雪など)
