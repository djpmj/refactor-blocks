# small-text-fixes: 遊んで見つかった小さな文言・表示の不具合をまとめて直す

## 背景・目的

チュートリアル2を遊んで、意味が通らない・誤解を招く小さな表示が3つ見つかった。

1. 100点のあとのカード(「なぜ分けるのか」)に、`同じ変更が 1 か所 → 1 か所 で済むようになりました。` と出る。
   `ChangePain.improved` は「直す場所が減った、または読む量が減った」で `true` になる。
   `ModifyAfter` はその場合に直す場所の行を出すため、直す場所の数が変わらず読む量だけ減ったときに、意味の通らない文になる
2. チュートリアル2の初期コードには、税の処理の受け皿として空の `TaxCalculator` が置いてある。
   これがクリア条件で `空のクラス・ファイル: 0件にする (今1件)` と出て、**消せばよい**ように読めてしまう(本当は中身を入れる受け皿)
3. ヘッダーの「減点の内訳」(`details`)を開いたままステージを切り替えると、開いたままになり、ツールバーのボタンに重なって押せない

## データ・型の変更

なし。

## 見た目・動きの仕様

### 1. 「なぜ分けるのか」の直す場所の行

- `ModifyAfter` の `同じ変更が A か所 → B か所 で済むようになりました。` は、`B < A`(直す場所が減った)ときだけ出す
- 読む量の行(`読む量は X 行 → Y 行 になりました。`)は今のまま(減ったときだけ)

### 2. 空のクラス・ファイルの条件の文

- クリア条件の `空のクラス・ファイル: 0件にする` を `空のクラス・ファイル: 0件にする(中身を入れるか、消す)` にする
- 未達成のときの今の値は今のまま(`今1件`)。`clear-condition-badges`(#162)が先にマージされていれば、その形(`今: 1件`)に合わせる

### 3. 減点の内訳

- ヘッダーの「減点の内訳」の `details` は、ステージを切り替えたら閉じる(`key={stage.id}` を付けて作り直す、または `open` を状態で持ってステージの切り替えで `false` にする)
- 変更依頼に挑戦し始めたときも閉じる

## TDD対象の純粋関数

### `describeCondition`(`presentation/stage/describeCondition.ts`)

- `{ rule: 'empty', count: 0 }` → `空のクラス・ファイル: 0件にする(中身を入れるか、消す)`
- `{ rule: 'empty', count: 1 }` → 上の文に今の値が付く
- ほかのルールは今のまま

`ModifyAfter` の出し分けと内訳の開閉は、表示の変更なので E2E で確かめる。

## 受け入れ基準

1. チュートリアル2を解答例どおりに100点にすると、「なぜ分けるのか」に `1 か所 → 1 か所` の文が出ず、`読む量は 31 行 → 8 行 になりました。` だけが出る
2. 直す場所が減るステージ(例: 中級9 のコピペされた消費税計算)では、今どおり `A か所 → B か所` の文が出る
3. チュートリアル2のクリア条件が `空のクラス・ファイル: 0件にする(中身を入れるか、消す)` になっている
4. 「減点の内訳」を開いたまま別のステージへ切り替えると閉じていて、ツールバーのボタンが押せる
5. `npm run check` と `npm run test:e2e` が通る

## スコープ外

- 最初から置いてある空の受け皿を減点しないようにすること(採点の変更)
- 「減点の内訳」の位置・見た目の変更
