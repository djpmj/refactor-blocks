# narrow-screen-layout: 幅の狭い画面では、左パネルと右パネルを重ねて出し、キャンバスを広く使う

## 背景・目的

2026-10-17 に画面幅 375px(スマホ相当)で開くと、左パネル(課題とヒント)・キャンバス・右のエディタのレール(「メソッドをクリック」)が
**3列のまま横に詰め込まれ**、キャンバスの幅が約180pxしか残らなかった。ブロックの文字はほぼ読めず、ドラッグもしにくい。
左パネルは文字が1行に4〜5文字しか入らず、縦に非常に長くなる。

幅 768px(タブレット相当)では使える範囲だった。新卒〜4年目のエンジニアが通勤中などにスマホで開くことは考えられるので、
少なくとも「読める・タップで選べる」状態にしたい。

## 見た目・動きの仕様(幅 700px 以下)

- キャンバスは画面の幅いっぱいに出す
- 左パネルは、閉じた状態ではキャンバスの左上の「課題とヒント」ボタンだけになる。押すと画面の幅の 85% のドロワーとしてキャンバスの上に重ねて開く。外側をタップするか、閉じるボタン・`Esc` で閉じる
- 右のメソッドエディタは、メソッドを選んだときにだけ、右から 85% 幅のドロワーで開く。閉じるボタン・`Esc` で閉じる。何も選んでいないときの案内レール(「メソッドをクリック」)は出さない
- ドロワーを開いている間は、後ろのキャンバスを操作できない(`inert` か、重ねた背景で受け止める)。閉じたら開いたボタンへフォーカスを戻す
- 初回ツアーで左パネルを照らす段では、左パネルを開いてから照らす(今の `setSidebarOpen(true)` を使う)
- 幅 701px 以上は今のまま

## 受け入れ基準

1. ビューポート 375x812 でチュートリアル1を開くと、キャンバスの幅が 340px 以上ある
2. 「課題とヒント」ボタンで左パネルが重ねて開き、閉じるとキャンバスに戻る
3. `printMonthlyReport()` をタップすると右からエディタが開き、処理を選んで抽出できる
4. 幅 1280px では今と同じ3列の配置
5. `npm run check` と `npm run test:e2e` が通る
