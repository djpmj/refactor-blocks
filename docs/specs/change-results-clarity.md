# change-results-clarity: 変更依頼の点数を2つの言葉にそろえ、依頼票と部品置き場の紛らわしさをなくす

## 背景・目的

チュートリアル2で変更依頼を3件こなすと、結果画面に次の4種類の点数が並ぶ。

- `変更容易性スコア: 83点(初期状態は 70点)`
- `実装スコア: 90点`
- 依頼ごとの `今のコード 95点 / 初期状態 70点`
- 依頼ごとの `置き方 100点`

同じものを別の名前で呼んでいる(「変更容易性スコア」は「今のコード」の平均、「実装スコア」は「置き方」の平均)ので、どれが自分の成績か分からない。

ほかにも、変更依頼の途中で紛らわしい表示が2つある。

- 依頼票の説明に、チュートリアルでも「新しいクラスは右クリックで継承元・実装するインターフェースを設定できます」と出る。
  継承をまだ習っていないステージでは、何のことか分からない
- 部品を置くと、空になった「部品置き場」に ⚠️(空のクラスの警告)と「ここにメソッドをドロップ」が出る。
  警告を消そうとして、置いた部品を戻したくなる

## 見た目・動きの仕様

### 点数の言葉

点数は次の2つだけにし、結果画面のどこでも同じ言葉で呼ぶ。

| 言葉 | 中身 | 今の呼び方 |
| --- | --- | --- |
| **変更のしやすさ** | 変更依頼をそのコードに入れるときのコスト(`ChangeOutcome.current` / `initial` の点数) | 変更容易性スコア・今のコード |
| **置き方** | プレイヤーが部品を置いた場所の点数(`placement.score`) | 実装スコア・置き方 |

### 結果画面(`Results`)

- 見出しの下に、2つの点数を同じ大きさで並べる(`data-testid` は今のまま)
  - `変更のしやすさ 83点`(下に小さく `組み替える前は 70点`)
  - `置き方 90点`
  - それぞれに、何の点数かの1行の説明を添える
    - 変更のしやすさ: `この設計に、依頼の変更を入れる手間(直す場所・読む量・行数の上限)`
    - 置き方: `あなたが部品を置いた場所が、自然な置き場所だったか`
- extend の依頼しかない場合は、変更のしやすさを出さない(今どおり置き方だけ)

### 依頼ごとのカード(`OutcomeCard`)

- `今のコード 95点 / 初期状態 70点` を `変更のしやすさ 95点(組み替える前は 70点)` にする。`前回 ○点` はそのまま後ろに付ける
- `置き方 100点(置いた先: TaxCalculator)` はそのまま
- 並びは「変更が必要な場所 → 変更のしやすさ → 置き方 → 解答例 → 減点の理由」にする

### 依頼票の説明

- `新しいクラスは右クリックで継承元・実装するインターフェースを設定できます。` の文は、`usesInheritance(stage)` が `true` のステージだけに出す
- `usesInheritance(stage)`: ステージの初期コードか解答例のコード(`sampleAnswerCodebase(stage)`)に、継承元(`superclass`)を持つクラスか、インターフェース役のクラス(`isInterfaceLike`)があれば `true`

### 部品置き場

- 変更依頼の途中で、部品置き場のクラスにメソッドが1つも無いときは、部品置き場のファイルをキャンバスに描かない
  (Ctrl+Z で部品が戻ったら、また描く)
- 部品置き場のファイル・クラスには、メソッドがあってもなくても、⚠️/⛔ の印・空のクラスの警告を出さない

## TDD対象の純粋関数

### `usesInheritance`(`presentation/change/usesInheritance.ts`)

- 初期コードに継承元を持つクラスがある → `true`
- 解答例のコードにだけインターフェース役のクラスがある → `true`
- どちらにも継承もインターフェースも無い(チュートリアル2) → `false`

## 受け入れ基準

1. チュートリアル2で変更依頼を3件こなすと、結果画面の見出しに「変更のしやすさ」と「置き方」の2つの点数だけが、説明つきで並ぶ
2. 依頼ごとのカードが「変更のしやすさ ○点(組み替える前は ○点)」と「置き方 ○点」になっている
3. チュートリアル2の依頼票に「継承元・実装するインターフェース」の文が無い。継承を扱う上級のステージでは出る
4. 部品を置くと部品置き場がキャンバスから消え、Ctrl+Z で部品が戻るとまた出る。部品置き場に ⚠️ は出ない
5. `npm run check` と `npm run test:e2e` が通る
