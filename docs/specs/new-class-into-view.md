# new-class-into-view: 余白へのドロップで作ったクラスが画面外にはみ出したら、見える位置へ寄せる

## 背景・目的

2026-10-17 に白紙設計で部品を次々に余白へドラッグしてクラスを作ったところ、キャンバスの下の方に落とすと、
新しいファイルの箱がキャンバスの下端からはみ出して半分しか見えなかった(`NewClass2`・`NewClass4`)。
次の部品を入れたいクラスが見えないので、毎回ホイールやパンで探す必要がある。

ドロップした位置にファイルの箱の左上を置く(`drop-new-file-at-position`)ため、下端・右端の近くに落とすほど、箱の大部分がはみ出す。
リファクタリングモードでも、余白へのドロップでクラス・ファイルを作るときは同じことが起きる。

## 振る舞い

- 余白へのドロップ(メソッド・部品・クラス)で新しいファイルの箱ができたら、描画が終わったあとに、その箱の矩形(画面座標)がキャンバスの表示領域に収まっているか調べる
- はみ出していれば、**ズームは変えずに**、はみ出した分だけ(余白 24px を足して)パンする(`setViewport` の `x`・`y` を動かす。`duration` は 200ms、`prefers-reduced-motion: reduce` なら 0)
- 箱が表示領域より大きいときは、箱の左上が見える位置を優先する
- 既存のファイル・クラスへのドロップでは動かさない

## TDD対象の純粋関数

### `panToReveal(box, viewport, margin)`(`presentation/canvas/panToReveal.ts`)

入力: 箱の矩形と表示領域の矩形(どちらも画面座標)、余白。出力: パンの移動量 `{ dx, dy }`。

- 収まっている → `{ dx: 0, dy: 0 }`
- 下に 100px はみ出す → `dy = -(100 + margin)`
- 右に 50px はみ出す → `dx = -(50 + margin)`
- 上・左にはみ出す → 正の向きに動かす
- 箱が表示領域より縦に大きい → 箱の上端が表示領域の上端 + margin に来る量

## 受け入れ基準

1. 白紙1で、部品をキャンバスの下端の近く(下端から 30px 以内)の余白へドラッグすると、できたファイルの箱全体がキャンバスの表示領域に収まっている
2. そのときズーム倍率は変わっていない
3. 既存のクラスへドロップしたときは、表示位置が動かない
4. `npm run check` と `npm run test:e2e` が通る

- ドラッグ中にキャンバスの端で自動スクロールすること
