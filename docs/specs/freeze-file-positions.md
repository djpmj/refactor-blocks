# メソッドを移しても、ファイルの箱の位置を勝手に変えない(「整列」ボタンで並べ直す)

## 背景・目的

キャンバスのファイルの箱の位置は、コードベースが変わるたびに `layoutCodebase`(`src/presentation/canvas/layoutCodebase.ts`)が
**依存・継承の向きから計算し直している**(呼ぶ側を上の段、呼ばれる側を下の段に置く)。プレイヤーが手でドラッグしたファイルの位置だけは
`useFlowOverrides`(`src/presentation/canvas/CodebaseCanvas.tsx`)が覚えているが、それ以外は毎回計算し直される。

そのため、チュートリアル2でメソッドを `TaxCalculator` へ移した瞬間に `OrderService → TaxCalculator` の依存が生まれ、
右に並んでいた `TaxCalculator` の箱が `OrderService` の下へ飛ぶ。ドラッグした先が直後に別の場所へ動くので、
何が起きたのか追えず、続けて操作しようとした場所も変わってしまう。

**一度表示したファイルの箱は、その場所に固定する**。依存の向きに沿って並べ直したいときは、新しく足す「整列」ボタンで今の計算を使う
(`docs/feature-ideas/IDEAS.md` 2026-10-10 の案9「依存グラフの自動整列ボタン」をここで実現する)。

## 振る舞い

- **固定**: ステージを開いたときは今どおり `layoutCodebase` の配置で表示する。以後、Extract Method・Move Method・Move Class・
  フィールドの移動・統合・削除などの操作をしても、**すでに表示されているファイルの箱の位置は変えない**(箱の中身が増減して大きさが変わるのは今どおり)
- **新しくできたファイル**:
  - 余白へドロップして作ったファイルは、今どおりドロップした位置に置く(`drop-new-file-at-position.md`)
  - それ以外の操作で新しくできたファイル(右クリックメニューからの操作など)は、**今あるファイル全体を囲む矩形の右隣**
    (矩形の上端にそろえ、`FILE_GAP` 空ける)に置く。同時に複数できたときは、その右へ順に並べる
- **整列ボタン**: キャンバスの右上(React Flow の `<Panel position="top-right">`)に「整列」ボタンを置く。押すと、固定していた位置と
  ドロップ位置をすべて捨てて、今のコードベースを `layoutCodebase` で並べ直し、全体が見えるよう `fitView` する
- **元に戻す・やり直し**: 残っているファイルの位置は変えない。消えたファイルが戻ってきたときは、消える前の位置に戻す
  (覚えた位置は、ファイルが消えても捨てない)
- **最初に戻す**: ステージを開いたときの配置(`layoutCodebase` の初期配置)に戻す。ステージを切り替えたときも今どおり初期配置から始める
- 手でドラッグして動かしたファイルの位置は、今どおり覚えておく(整列・最初に戻すでは捨てる)

## 変更対象ファイル一覧

### 新規

- `src/presentation/canvas/keepFilePositions.ts`(presentation): 配置を決める純粋関数
  - `placeFiles(layoutNodes, known, existingRects)` のような形で、`layoutCodebase` の結果のうち、すでに位置を知っているファイルはその位置に、
    知らない(新しくできた)ファイルは上の「新しくできたファイル」の規則の位置に置き、確定した位置の一覧を返す。React に依存しない
- `src/presentation/canvas/keepFilePositions.test.ts`: 上の関数のテスト(下記)

### 変更

- `src/presentation/canvas/CodebaseCanvas.tsx`(presentation)
  - `useFlowOverrides` を、「ドラッグした位置だけ覚える」から「表示したファイルの位置を全部覚える」に変える。初めて表示したファイルの位置を
    `placeFiles` で確定して覚え、以後のレンダリングではその位置を使う
  - 「整列」ボタン(`data-testid="canvas-arrange"`、`aria-label="依存の向きに沿って並べ直す"`、表示は「整列」)を `<Panel position="top-right">` に置く。
    押したら覚えた位置を捨てて `fitView` する。dnd-kit のドラッグと干渉しないよう `nodrag nopan` を付ける
  - 「最初に戻す」で覚えた位置を捨てる。キャンバスがリセットを知る手段として、`useGameStore` に配置を捨てる合図
    (例: `resetStage` と、ステージの読み込み時に増える `layoutResetCount: number`)を足し、値が変わったら位置を捨てる
- `src/presentation/store/useGameStore.ts`(presentation): 上の合図を足す。`undo`/`redo` では増やさない
- `src/presentation/canvas/layoutCodebase.ts`: 変更しない(初期配置と整列で今の計算をそのまま使う)。
  `FILE_GAP` など新しい関数で使う定数は export する
- `e2e/`: 下の受け入れ基準のうち、操作に関わるものを追加する(新しいファイル `e2e/freeze-file-positions.spec.ts`)。
  既存のE2Eで、操作のあとに自動で並べ直される位置を前提にしているものがあれば、「整列」ボタンを押す手順を足すか、期待値を直す

## データ・型の変更

- `useGameStore` に `layoutResetCount: number`(「最初に戻す」・ステージの読み込みで1増える)を足す。保存形式(自動保存)には含めない
- ドメインモデル(`src/domain/`)の変更はない。ファイルの位置は今どおり画面の状態(presentation)で持ち、自動保存しない
  (リロードすると初期配置から表示される。今と同じ)

## TDD対象の純粋関数

`domain`/`application` のロジックは増えない。配置の規則は壊れやすいので、presentation の純粋関数 `placeFiles` も先にテストを書く
(`layoutCodebase.test.ts` と同じく Vitest)。

- 知っているファイルだけ → すべて知っている位置のまま(依存の向きが変わっていても動かない)
- 知らないファイルが1つ → 今あるファイル全体の矩形の右隣(上端そろえ、`FILE_GAP` 空ける)
- 知らないファイルが2つ → 右隣に順に並び、互いに重ならない
- ドロップ位置を持つ新しいファイル → ドロップ位置を優先する
- 知っている位置の一覧に、もう存在しないファイルの位置が残っていても無視する(消えたファイルの位置は捨てずに持っておける)
- 何も知らない(ステージを開いた直後・整列直後) → `layoutCodebase` の位置そのまま

## 受け入れ基準

- `npm run check` と `npm run test:e2e` がすべて通る
- チュートリアル2で、`placeOrder` から処理を抽出して `TaxCalculator` へドラッグで移したとき、`TaxCalculator` と `OrderService` の
  ファイルの箱の位置(`boundingBox` の x・y)が移す前と変わらない
- 「整列」ボタンを押すと、依存の向きに沿って並び直る(チュートリアル2の上の状態では、`TaxCalculator` が `OrderService` の下に来る)
- 「元に戻す」を押しても、残っているファイルの箱の位置は変わらない
- 「最初に戻す」を押すと、ステージを開いたときの配置に戻る
- 右クリックメニューなどで新しいファイルができたとき、既存のファイルの箱と重ならない位置(全体の右隣)に出る。余白へドロップして作ったときはドロップ位置に出る
- 手でドラッグしたファイルは、その後の操作でも動かない
- 「整列」ボタンはキーボードで操作できる(Tab でフォーカスでき、Enter / Space で押せる)

## スコープ外

- ファイルの位置の自動保存(リロード後も同じ配置にすること)
- ファイルの箱が大きくなって、下や右の箱と重なったときに自動でずらすこと(「整列」か手で直す)。
  実装では `// ponytail: 箱が育って重なっても動かさない、重なりの苦情が出たら下の箱だけ押し下げる` のようにコメントを残す
- 箱の移動のアニメーション
- クラス(ファイルの中の並び)の位置の固定(ファイルの中は今どおり上から順に並べる)
- 設計くらべ・解答例の図・解答の再生のプレビュー(こちらは今どおり毎回 `layoutCodebase` で並べる)
