# 左サイドバー(課題)を、初期表示で上限の幅(480px)にする

## 背景・目的

左の「課題」サイドバー(`StagePanel.tsx` の `aside.sidebar`)は、`resizable-left-sidebar` でドラッグ・キーボードで
200〜480px に広げられるようになったが、初期表示は 260px のままである。課題文・クリア条件・ヒント・ストーリーが長く、
260px では縦に長くなって読みにくいため、プレイヤーは毎回自分で広げている。
最初から上限の 480px で開き、広げる手間をなくす。狭めたいプレイヤーは従来どおりドラッグ・キーボードで狭められる。

## 変更対象ファイル一覧

### 変更

- `src/presentation/stage/StagePanel.tsx`(presentation): `useStageSidebarWidth` の `defaultWidth` を `260` から `480` にする。
  `minWidth: 200`・`maxWidth: 480` は変えない。マジックナンバーを2か所に書かないよう、上限と初期値は同じ定数を使う
  (例: `const STAGE_SIDEBAR_MAX_WIDTH = 480`)
- `src/index.css`(presentation): `var(--sidebar-width, 260px)` のフォールバック値(`.sidebar`・
  `.app__body--sidebar-open > .sidebar-toggle`・`.sidebar-resizable__handle--left`)を `480px` にそろえる。
  実際の幅はインラインの `--sidebar-width` で渡るので見た目は変わらないが、初期値と食い違う数字を残さない
- `e2e/sidebar-toggle.spec.ts`: 既定幅 `260` を前提にしている `aria-valuenow` の期待値(初期表示・リロード後)を `480` にし、
  ドラッグ・キーボード操作の手順を「480から狭める」形に組み替える(右ドラッグで上限を超えない、左ドラッグで狭まる、
  ← で16px狭まる、閉じて開き直すと調整した幅を保つ、リロードで480に戻る)
- `e2e/refactor.spec.ts`: 「左サイドバーの幅を変えても右サイドバーの幅は独立している」の `ArrowRight` → `276` を、
  初期480から `ArrowLeft` → `464` に置き換える

## データ・型の変更

なし。幅は `useResizableSidebarWidth` の `useState` が持つ画面表示専用の一時的な状態のまま。

## TDD対象の純粋関数

新しい純粋関数はない。初期幅は既存の `clampSidebarWidth`(`clampSidebarWidth.test.ts` でテスト済み)で範囲に収められる。
変更はプレイヤーの見た目に関わるため、E2Eの期待値を先に 480 に書き換えて失敗させてから実装する(Red→Green)。

## 受け入れ基準

1. 横幅の広い画面(例: 1440×900)で初めて開いたとき、左サイドバーの幅が 480px で、ハンドルの `aria-valuenow` が `480`
2. 初期状態からハンドルを右へドラッグしても、→ を押しても、幅は 480 のまま(上限を超えない)
3. 左へドラッグ・← で狭められ、下限 200px を下回らない(1回の ← で16px)
4. 幅を変えたあと閉じて開き直すと調整した幅で開き、リロードすると 480 に戻る
5. 開閉ボタン(`«`/`»`)の左端がサイドバーの右端に接している(差は 0〜2px)
6. 狭い画面(700px以下)のドロワー表示(85vw で重ねる)は変わらない(初期幅は既存の `effectiveBounds` の範囲に収まる)
7. 右サイドバー(メソッドエディタ)の幅・表示は変わらない
8. `npm run check` と `npm run test:e2e` が通る

## スコープ外

- 幅の上限・下限の変更、画面幅に応じた初期幅の計算
- 幅の永続化(`localStorage` など)。従来どおりリロードで初期値(480px)に戻る
- 右サイドバー(メソッドエディタ)の初期幅
- 設計くらべ・白紙設計など、`StagePanel` を使わない画面
