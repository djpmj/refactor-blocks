# boss-result-and-layout-fixes: 鬼の変更の比較欄に指標名を付け、細かい表示崩れを直す

## 背景・目的

2026-10-17 に初級1の変更依頼(鬼の変更あり)や上級3を遊んで、次の表示の分かりにくさ・崩れが見つかった。

1. **鬼の変更の点数が2種類混ざって見える**: 鬼の変更の結果カードの上部は「変更のしやすさ 75点(組み替える前は 40点)」、
   その下の比較欄(`BossComparison`、`boss-comparison`)は「組み替える前のコードなら 最善の置き方でも 90点 / あなたの設計では 100点」、
   まとめの文(`describeBoss`)は「鬼の変更も 100点で入れられた(組み替える前なら最善でも 90点)」と出る。
   比較欄とまとめの文は**置き方**の点数だが、右側とまとめの文には指標名が無いので、同じカードに 75点と100点、40点と90点が並んで、どれが本当の点か分からない
2. **メソッド行の行数が折り返す**: 手直し中に「✔ 直した」印が付いたメソッド(チュートリアル1の `printMonthlyReport()`)で、右端の `39行` が `39` と `行` の2行に折り返す
3. **クラス名と責務のバッジが詰まる**: 上級3の `DiscountService` のように名前が長いクラスで、見出しのクラス名と `責務 4種類(上限 2)` のバッジの間に隙間が無く、続けて読めてしまう
4. **うわさの引用のカギ括弧が二重になる**: 変更依頼の「うわさが本当になりました: 「…」」で、うわさの文がカギ括弧で始まると
   `「「データの残し方」を変えたいという話が…」` と `「「` が並んで読みにくい

## 見た目・動きの仕様

### 1. 鬼の変更の比較欄

- 比較欄の見出しの上に `鬼の変更の置き方の点数で比べています` を1行出す
- 左(組み替える前): 今のまま `最善の置き方でも <before>点`
- 右(あなたの設計): `<now>点` を `置き方 <now>点` にする
- まとめの文(`describeBoss`):
  - 良くなったとき: `<thanks>、鬼の変更も置き方 <now>点で入れられた(組み替える前なら最善の置き方でも <before>点)`
  - 良くならなかったとき: 今のまま
- カード上部の「変更のしやすさ」の行は変えない

### 2. メソッド行の行数

- キャンバスのメソッド行の行数(`<n>行`)は `white-space: nowrap` で折り返さない。幅が足りないときはメソッド名の側を省略(`text-overflow: ellipsis`)するか折り返す

### 3. クラス見出し

- クラス名と責務のバッジの間に最低 8px の隙間を空ける
- 1行に入りきらないときは、バッジを次の行へ回す(`flex-wrap: wrap`)。クラス名とバッジは重ならない

### 4. うわさの引用

- `うわさが本当になりました: 『<うわさの文>』` にする(外側を『』にして、うわさの文の中の「」と区別する)

## TDD対象の純粋関数

### `describeBoss`(`presentation/change/describeBoss.ts`)

- 今 100点・前 60点・`openingTitle` あり → `冒頭の「軽減税率の対象を増やして」の処理を切り出しておいたおかげで、鬼の変更も置き方 100点で入れられた(組み替える前なら最善の置き方でも 60点)`
- 今 100点・前 60点・`openingTitle` なし → `組み替えておいたおかげで、鬼の変更も置き方 100点で入れられた(組み替える前なら最善の置き方でも 60点)`
- 今の点数が前以下 → 今のまま

2〜4は表示の変更なので、E2E または目視で確かめる。
