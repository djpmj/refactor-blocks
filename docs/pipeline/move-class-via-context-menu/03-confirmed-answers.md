# 確定した回答: move-class-via-context-menu

- 元になった草案: `docs/pipeline/move-class-via-context-menu/02-draft-spec.md`

## 未決事項1: 「別のファイルへ移動」をどこを右クリックしたときに出すか

**確定: 選択肢A** — クラスヘッダー(クラスノードのメソッド・フィールド以外の部分)を右クリックした
ときだけ(`classId !== null && member === null`)。メソッド上の「別のクラスへ移動」と並ばず紛らわし
くない。

## 未決事項2: 「新しいファイルへ移動」(`moveClassToNewFile`)も候補に入れるか

**確定: 選択肢A** — 入れない。01-discovered.md の分割案どおり後回しにし、既存ファイルへの移動だけに
する。前回もメソッドの「新しいクラスへ移動」は入れておらず揃う。

## 未決事項3: 候補の表示

**確定: 選択肢A** — ファイルのパスをそのまま並べる(例: `src/shipping/ShippingService.ts`)。キャン
バスのファイルの箱・メニュー上部のキャプションと同じ表記で、同名ファイルが別ディレクトリにあって
も区別できる。

## 未決事項4: メニューのどこに置くか

**確定: 選択肢A** — 先頭に置く。クラスヘッダーを右クリックしたときの主目的で、前回の「別のクラス
へ移動」と同じく開いた時点で先頭にフォーカスが入り、サブメニューも開く。既存の先頭項目(「この
ファイルにクラスを追加」)が2番目になる場合は、既存E2Eの前提を直してよい。

## 未決事項5: 移動先候補が無いとき(ファイルが1つだけ)の扱い

**確定: 選択肢A** — 項目自体を出さない(`MoveMenuItem` と同じく `null` を返す)。
