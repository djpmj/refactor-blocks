# 確定した回答: move-via-context-menu

- 元になった草案: `docs/pipeline/move-via-context-menu/02-draft-spec.md`

## 未決事項1: メニューをキーボードからも開けるようにするか

**確定: 選択肢A** — ブラウザ標準に任せる。フォーカスしたチップで Shift+F10 / ContextMenu キーを
押すと、Chrome・Firefox(Windows/Linux)はネイティブに `contextmenu` イベントを出すので追加コードは
無し。E2Eで `press('Shift+F10')` が効くことを確かめ、効かなければ実装者は独自実装に進まず報告する。

## 未決事項2: 「新しいクラスへ移動」(`moveMethodToNewClass`)も候補に入れるか

**確定: 選択肢A** — 入れない。余白へのドロップで既にでき、キーボードで使いたい要望も今は無い
(YAGNI)。フィールドには同等の操作が無いので、メソッドとフィールドの見た目も揃う。

## 未決事項3: 移動先の候補をどう並べるか

**確定: 選択肢A** — 移動元以外の全クラスをファイル順・宣言順にクラス名だけで並べ、同名のメソッド/
フィールドを既に持つクラスは除く(「継承元を設定」が選べない相手を除くのと同じ方針)。インター
フェース役のクラスも除かない(ドラッグと同じ)。

## 未決事項4: メニューを閉じたときにフォーカスをどこへ戻すか

**確定: 選択肢A** — Escape・外側クリックで閉じたときは、開く前にフォーカスしていた要素(チップ)へ
戻す。移動を実行した場合はチップが別クラスへ移って作り直されるので戻さない(フォーカスはbodyになる)。
