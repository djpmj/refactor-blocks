# ユーザー確認後の修正キュー

`docs/pipeline/README.md` のパイプラインが実装したPRをユーザーが実際に動かして見つけた、
直してほしい内容をここに追記する。`docs/auto-dev/TASKS.md` と同じ書式。

## 使い方

- 気づいた内容は1見出しにつき1件、下の書式で追加する
- パイプラインの機能探索ステージ(`.claude/agents/feature-scout.md`)は、新しい機能を
  自分で探す前に**必ずこのファイルの未完了項目(`### [ ]`)を確認し、あれば最優先でそれを
  次の仕様設計の元にする**。空のときだけ新規機能を探す
- 仕様設計が終わり `docs/pipeline/<機能名>/01-discovered.md` に取り込まれたら、
  該当する見出しを `### [ ]` から `### [x]` に書き換える
- 優先度の高いものほど上に置く
- ファイルが肥大化しないよう、直近30件までとし、31件目以降(古い完了済み)は削除する
  (削除した内容はgit履歴 `git log -p docs/pipeline/USER_FIXES.md` から参照できる)

## 書式

```
### [ ] 直してほしい内容のタイトル

- 気づいた状況(どのステージ・どの操作で気づいたか)
- 期待する動き / 直してほしい内容
- 関連ファイル・参考情報(あれば)
```
