# 03 ユーザ確定: クラス・ファイルの削除で本物の処理が消えないようにする

- slug: `delete-class-code-guard`
- 元になった仕様草案: `docs/pipeline/delete-class-code-guard/02-draft-spec.md`

## 未決事項1: 契約メソッド(`fragments: []`)だけを持つインターフェース役のクラス・ファイルを削除できるようにするか

**確定: 選択肢A(拒む)**

`has-code` で拒む。消せるのは「空実装だけ(0個を含む)」のクラスに限る。`deleteMethod` で1つずつ消せるものだけ、とそろい、上級2で PaymentGateway.ts を消して約束違反の減点を逃れる近道も塞がる。

## 未決事項2: 失敗の種類をいくつに分けるか

**確定: 選択肢A(`has-code` 1つにまとめる)**

「本物の処理が残っている」も「戻せない切り出しメソッドがある」も、どちらも「先にメソッドを別のクラスへ移す」で解決できるので、文言も1つで足りる。

## 未決事項3: 変更依頼・白紙設計で、部品を置いたクラスの削除も拒むか

**確定: 選択肢A(モードに関係なく拒む)**

部品は本物の処理なので、消したいときは部品置き場へドラッグで戻すのが正しい手順になる。`changePart.test.ts`・`measurePlacement.test.ts` を02-draft-spec.md 5章のとおり書き換える。

## 未決事項4: 切り出したメソッドを public にしたクラスを削除しようとしたときの扱い

**確定: 選択肢A(削除を拒む)**

戻せないので削除を拒む(`has-code`)。`inlineMethod` は変えない。

## 実装者への申し送り

未決事項1〜4すべて推奨案(A)が選ばれたため、`02-draft-spec.md` の本文(2章〜5章)に書かれた内容をそのまま実装の正本とする。追加の分岐・条件は無い。
