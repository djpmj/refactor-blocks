# 自動開発タスクキュー

`.github/workflows/auto-dev.yml` が参照するタスクリスト。
Claude Codeがこのファイルを上から順に読み、`### [ ]` の未完了タスクを1件実装・コミット・pushしたら、
そのまま次の未完了タスクに進む――というのを、未完了タスクがなくなるか、その回の実行時間・トークンを
使い切るまで繰り返す(1回の実行で1件とは限らない)。

## 使い方

- タスクは1見出しにつき1件、下の書式で追加する
- 完了したタスクは自動実行によって `### [x]` に書き換えられ、コミットされる
- `npm run check` を通せず自動実装を断念したタスクは `### [!]` に書き換えられ、
  対応するIssueが作成される。自動実行の対象から外れるので、原因を解消してから
  手動で `### [ ]` に戻すこと
- 優先度の高いタスクほど上に置く
- ファイルが肥大化しないよう、**タスクは直近30件までとし、31件目以降(古い完了済みタスク)は
  削除する**。削除したタスクの内容はgit履歴(`git log -p docs/auto-dev/TASKS.md`)から参照できる
- 大きすぎるタスクは1回の自動実行(1コミット)で完結しないことがあるため、小さく分割する

## 書式

```
### [ ] タスクのタイトル

- 背景・目的
- 実装してほしい内容(受け入れ条件)
- 関連ファイル・参考情報(あれば)
```

## タスク一覧

### [x] メソッドの統合(Inline Method)を追加する

- 背景・目的: 分解だけでなく「分けすぎたものを戻す」操作も学ばせたい。
- 実装してほしい内容(受け入れ条件):
  - `src/domain/codebase/inlineMethod.ts` に、private メソッドの処理を呼び出し元の呼び出し行(`<id>:call`)の位置へ戻す純粋関数を追加する(TDD、`Result`型で失敗を返す)
  - 呼び出し行が見つからない・public メソッドを指定した、などはエラーにする
  - メソッドエディタに「呼び出し元へ戻す」ボタンを追加し、E2Eテストを1件追加する
- 関連ファイル: `src/domain/codebase/extractMethod.ts`

### [x] クラスの新規作成とファイルの新規作成をできるようにする

- 背景・目的: 現状は用意されたクラスにしかメソッドを移せない。責務ごとに自分でクラス・ファイルを作らせたい。
- 実装してほしい内容(受け入れ条件):
  - `domain/codebase` に `addClass(codebase, fileId, className)` と `addFile(codebase, path)` を追加する(同名チェックあり、TDD)
  - キャンバス上部に「クラスを追加」「ファイルを追加」のボタンを置く
  - クラスを別ファイルへドラッグで移動できる(`moveClass`)
- 関連ファイル: `src/presentation/canvas/`

### [x] 責務の混在を採点する

- 背景・目的: 行数だけでなく「1クラスに責務が混ざっていないか」を評価したい。
- 実装してほしい内容(受け入れ条件):
  - `src/domain/scoring/` に、クラスごとの Fragment の `responsibility` の種類数を数えるルールを追加する(`call` は数えない)
  - ステージ定義に「1クラスあたりの責務の上限」を持たせ、画面上部の状態表示に違反を出す
  - プレイヤーには `responsibility` の値そのものは見せない

### [x] 依存関係を React Flow のエッジで表示する

- 背景・目的: パターンBの「触った結果がその場で見える」手応えの中心。
- 実装してほしい内容(受け入れ条件):
  - Fragment に `uses`(参照するメソッドID)を追加し、クラス間の依存をドメイン層で算出する(TDD)
  - クラスノード間に依存の矢印を描き、循環依存は赤で表示する
  - メソッドを移動すると矢印がその場でつなぎ変わることをE2Eで確認する

### [x] セマンティックズームを入れる

- 背景・目的: 4段の入れ子を1枚のキャンバスに出すと見づらい。
- 実装してほしい内容(受け入れ条件):
  - ズーム倍率が低いときはファイルとクラス名だけ、高いときはメソッドと行数まで表示する
  - React Flow の `useStore` でズーム倍率を取得し、閾値は定数にまとめる
